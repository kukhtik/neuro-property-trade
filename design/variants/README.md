## Той же линейкой, что и в игре

В репозитории уже есть гейт, который мерит ровно R-1/R-2 на кадрах САМОЙ игры — `FILL`
(в карантине, добавлен коммитом `14edb3d`). Его вердикт на сегодняшних кадрах:

```
$ G="$(tools/ci/godot_bin.sh)"; "$G" --headless --path game res://tools/gates/fill_gate.tscn
FILL turn-human_neuro 1600x1200: R-1 пустых ячеек 55.1% (порог <= 25%)
FILL turn-human_neuro: R-2 центр [447,149 701x701] занято 2.2% (порог >= 70%)
==> FILL FAILED: turn-human_neuro: R-1 55.1% кадра не рисует ничего (порог 25%) | …
```

То есть сегодня продукт: **55.1 % кадра не рисует ничего, внутри кольца занято 2.2 %**. Мои три
макета на той же сетке 40×30 и том же пороге «< 2 % не-фоновых пикселей» дают **0–3.7 %** пустых
ячеек и **99.3–100 %** занятости центра. (Обе цифры — про топологию: «нет участка без графики».)

Оракул при этой работе: `tools/ci/run_tests.sh` → `==> ORACLE PASSED (406 tests, 0 SCRIPT ERROR)`,
exit 0. Правка — только новые файлы в `design/variants/`, кода игры не касается; `FILL` выше назван
красным не из-за неё, а потому что центр доски в игре всё ещё пуст (это и есть предмет переработки).


## Чем это сделано

- **OpenDesign** (демон `~/open-design`, node 24, порт 7456) как носитель задачи: проект
  `NPT — варианты переработки UI (v4)` = `f072105f-1c3b-4aed-ae2d-229cec24a1da`.
- **Агент `opencode`**, модель **`opencode/deepseek-v4.1-flash-free`** (провайдер opencode).
  Три прогона: `od run start --project <id> --agent opencode --model opencode/deepseek-v4.1-flash-free
  --prompt-file <промпт> --follow`. Ран №2 с первого раза упал с `empty_output` — тот же промпт,
  повторный запуск дал файл (транзиентная ошибка провайдера, не дефект промпта).
- Промпты (по одному на вариант) + `scene-data.md` — не в репозитории (они в истории OD-проекта);
  `scene-data.md` скопирован сюда, потому что он и есть «источник данных» макетов.
- **Обязательная деталь окружения**: `opencode` отказывается читать файлы вне рабочей папки
  (`permission requested: external_directory … auto-rejecting`) — первый прогон на этом и умер.
  Лечится либо копированием файлов в папку проекта (сделано: `files/`), либо `opencode.json` с
  `{"permission":{"external_directory":"allow"}}` в папке проекта (тоже сделано, чтобы агент мог
  читать `design/ui-prototype.html`).

## Как воспроизвести замеры

```bash
# рендер 1600×1200 + геометрия доски (нужен Python 3.12 с playwright)
py -3.12 design/variants/tools/render_variants.py design/variants/renders design/variants/variant-*.html
# R-1 / R-2 (Pillow): фон — токен скина, иначе угол кадра
py -3.12 design/variants/tools/measure_fill.py --bg "#0b0613" design/variants/renders/variant-*.png
# содержимое и запреты R-4/R-9/R-10/R-15 (текст файла)
py -3.12 design/variants/tools/check_variants.py design/variants/variant-*.html
# R-7: кегли «glance»-элементов и самый крупный текст в центре кольца
py -3.12 design/variants/tools/glance_probe.py design/variants/variant-*.html
```

Калибровка инструмента: `measure_fill.py` на живом кадре игры
(`build/ab/turn-human_neuro.png`, 1600×1200) даёт **51.8 % пустых ячеек** — в брифе §1 стоит
**51.7 %**. То есть замер сравнивает варианты с текущим продуктом той же линейкой: 51.8 % → 0…3.7 %.

## Что замеры говорят честно (ограничения)

1. **R-1 измеряет топологию, а не смысл.** Ячейка считается непустой, если в ней ≥2 %
   не-фоновых пикселей, — поэтому залитая панель «непустая», даже если несёт две строки текста.
   Второе число брифа (доля пикселей смысла ≥ 40 %) здесь не измерялось: для макетов его нельзя
   посчитать тем же способом, что для игры (в макете нет проекции, по которой считается смысл).
   Поэтому «0 % пустых ячеек» у V2/V3 — это «нет участков без графики», а не «нет воздуха».
2. **R-2 считался по геометрии доски**, найденной в DOM (контейнер из 40 клеток), а не по пикселям:
   центр = рамка доски минус одна клетка с каждой стороны. Числа 99–100 % означают «внутри кольца
   нет пустого прямоугольника», а не «центр заполнен на 100 % смыслом».
3. **R-7 замерен на канве 1600×1200, а не 1920×1080.** Бриф нормирует ≥59 px при 1920×1080
   (≥12 px после сжатия до 390 px); прогон на канве 1600 задавал агентам порог ≥20 px, и замер
   проверяет именно его. Настоящий гейт `STREAM-READ` для этого всё равно нужен в игре (Х-1).
   Кегли подписей-«капсов» (`ХОД`, `ФАЗА`) остаются 12–14 px — это подписи, не значения; значения
   крупнее (V3: фаза 14 px — самое мелкое место всех трёх вариантов).
4. **Скриншот — не гейт.** llvmpipe/SwiftShader-скриншоты в этом репозитории объявлены
   недостоверными; здесь кадры сняты Chromium (Playwright) с настоящей вёрсткой, 0 ошибок консоли,
   и служат только для глаза владельца. Решение «какой вариант идём внедрять» — за владельцем.
5. **Статическая проверка ищет 4 строки журнала**, а V2/V3 по заданию показывают 3 последние —
   поэтому у них 21/22, а не 22/22. Это ограничение проверки, а не дефект вариантов.

## Что в этих макетах не проверено и не сделано

- Ни один вариант **не внедрён в игру**: это макеты статичного состояния, не код Godot.
  Внедрение — шаги 2–6 §7 брифа (`FILL`-гейт → панно → переезд рейлов → кегли → гейты → доки).
- Гейты `FILL` и `PANEL-NOT-EMPTY` (Х-4) не написаны; `STREAM-READ` остаётся красным в карантине
  намеренно (Х-1).
- Панно не проверено на связке с проекцией (R-14), в вариантах не разведены состояния
  «мой ход / ИИ / наблюдатель» (R-6): взят один кадр — «идёт матч, ход человека».
- Эмодзи и значки в макетах отсутствуют (R-9/R-10 за проверкой), но `GLYPH`-гейт в игре это ещё
  не подтверждал.
