# NPT UI v3 — дизайн-система «Broadcast Table»

> **Статус:** действующий дизайн (спека `docs/specs/ui-full-redesign-spec.md`, §7.1.1).
> **Файлы поставки:** `design/DESIGN.md` (этот документ), `design/ui-prototype.html` (прототип),
> `design/tokens.json` (токены в форме скина), `design/coverage.md` (карта F/P + интеграция).
> **Доп.:** `design/regions.json` (реестр регионов), `design/i18n.json` (563 ключа игры, выгружены),
> `design/src/*` (исходники прототипа), `design/tools/*` (сборка и проверки), `design/renders/`
> (PNG всех состояний для двух стилей).

Открыть прототип: двойной клик `design/ui-prototype.html` — офлайн, без сети и сборки.
Пересобрать после правок: `python design/tools/build_data.py && python design/tools/build_prototype.py`.
Проверить согласие с игрой: `python design/tools/check_package.py`.

## 1. Концепция

**Broadcast Table** — интерфейс читается как приборный стол трансляции: тёмное поле с
тонкими линиями, вырезы-фаски на главных поверхностях (токен `shape.chamfer`), цифры —
моноширинные, акцент — один на решение. Пять принципов, из которых выведено всё остальное:

1. **Доска — герой.** Кольцо целиком в каждом состоянии, всегда; кинокамера — опция и
   по умолчанию выключена (P-1). Панели обслуживают доску, не спорят с ней.
2. **Две роли текста — и только две.** Значение (никогда не переносится) и абзац
   (переносится по словам). Ни один элемент не полагается на третью (P-3, P-4).
3. **Один герой-экшен.** В консоли одна акцентная кнопка (то, что решает ход), остальное —
   видимые, но спокойные вторичные кнопки с тултипами (P-7). Ничего не спрятано в микро-ссылки.
4. **Уведомление не поверх игры.** Хост тостов живёт в правом доке (десктоп) или строкой
   внутри консоли (компакт) — панель действий и клетки не перекрываются никогда (P-5, F-68).
5. **Токен до последнего пикселя.** Ни одного цвета/размера вне скина; каждый скин полон и
   рисует себя целиком (P-14, I-6). Прототип сверяет палитры со `skin.json` байт-в-байт.

## 2. Токены

Источник значений цвета — `game/assets/skins/<id>/skin.json` (существующие ключи не
переименовываются). Дизайн добавляет **семь новых токенов** (значения — в `tokens.json`,
раздел `per_skin.*.color_new`):

| Токен | Роль | neuro | evil | default |
|---|---|---|---|---|
| `scrim` | затемнение под модалками/оверлеями | `#0b0613b8` | `#080406b8` | `#16191fb8` |
| `glow` | свечение активной клетки/фокуса | `#ff6fae55` | `#e8264f55` | `#4fb3d955` |
| `good` | «норма» таймера, дома | `#2fa862` | `#2fa862` | `#3f8f5f` |
| `ring_bg` (у default) | фон кольца таймера | — | — | `#39404d99` |
| `group` (у default) | палитра групп клеток | — | — | набор classic |
| `player[6..7]` | места 7–8 (в скинах сегодня 6 цветов) | `#ffd166 #8f9bff` | те же | `#46c8b8 #d46a9e` |
| `motion.fast/base/slow` | длительности UI (0.12/0.19/0.32 c) | одинаково | | |

Все остальные значения — из существующих токенов: `bg, surface.1..3, line, text, muted,
accent, on_accent, accent2, money, danger, warn, ink, dice_bg, dice_ink, ev.*, board.bg2/3,
ring_bg, group.*, player[0..5]` + неффктовые: `size 10/12/13/18/28`, `space 4/8/12/16/24`,
`shape {radius 0, chamfer 9, chamfer_small 6, line 1, line_active 2}`, `metrics`, `motion`.

**Рецепт добавления нового значения (адаптивность к будущему):**
1. Сначала спросить: можно ли выразить существующим токеном (обычно да — `surface.2/3`,
   `line`, `accent` покрывают интерфейс).
2. Если нет — новый ключ в `tokens.color` **каждого** скина (полнота обязательна; проба
   `skin_probe` ловит неполные скины), затем `design/tokens.json`, затем использование в
   прототипе. Порядок именно такой: игра → контракт → макет.
3. Никаких `Color(...)` в компонентах; статическая проверка (этап 8) держит нулевую базу.

## 3. Две роли текста (контракт P-3/P-4)

| Роль | Класс в макете | Поведение | Примеры |
|---|---|---|---|
| **Значение** | `.t-value` (+ `data-trole="value"`) | не переносится; ширина по содержимому; в строке не растягивается | `$1500`, `×2`, `12:04`, бейджи, чипы, счётчики, имена в строках |
| **Абзац** | `.t-para` (`data-trole="para"`) | переносится по словам; занимает ширину родителя | подсказки действий, правила, текст журнала, пустые состояния, справка |

- Числа дополнительно несут `.num` (моноширинные, табличные цифры).
- **Правило оси:** в гибкой строке растягивается ровно один элемент, и он помечен
  `data-grow`. Аудит в прототипе считает нарушения живьём (полоса внизу страницы).
- **Эллипсис — последний резерв:** только для однострочных имён в узких местах (компактная
  клетка, рейлы). Текст клетки: перенос по словам, максимум две строки, кламп вместо обрезки
  посреди слова (P-8). Иконки клетки и текст разведены блоками.
- В коде это **уже существующие фабрики** `UiTheme.label` (значение: `AUTOWRAP_OFF` +
  `SHRINK_BEGIN`) и `UiTheme.label_wrap` (абзац: `WORD_SMART` + `EXPAND_FILL`) — макет лишь
  фиксирует контракт и запрет третьего поведения.

## 4. Типографика и числа

- Шкала — только токены скина: `xs 10` (бейджи, теги), `s 12` (caps-метки, меты),
  `m 13` (тело, кнопки), `l 18` (заголовки панелей, крупные суммы), `xl 28` (победитель).
- CAPS-метки всегда с трекингом ≥ 0.08em (иначе «дёшево» — и это правило проверяет линтер OD).
- Кириллица длиннее английского: запас длины в кнопках и табах закладывается на RU
  (перенос в кнопке запрещён контрактом значения → кнопка растёт шириной, консоль — переносом
  рядов). Длинные строки — только абзацем.
- Деньги — `$N` моно-цифрами, цветом `money`; время — `чч:мм` моно.

| **Модалки** | title · body · footer; scrim; один экземпляр | auction (свой/наблюдение), trade, trade-in, build, confirm, over, message | закрытие: scrim/ESC/кнопка; каскадов нет (P-9); ставки — только у текущего биддера (движок решает) |

## 6. Адаптив

| Профиль | Условие | Что меняется |
|---|---|---|
| wide | ≥1600px | доки 280/380, зазоры 12 |
| desktop | ≥1280px и высота >700 (дизайн-размер 1440×900) | доки 268/344, консоль 96 |
| compact | <1280px или высота ≤700 | доки → рейлы 48px + дроверы 320; wordmark/шаги скрыты; чипы раунда/банка — только числа; клетки могут перейти в компакт (<44px) |
| min | 880×600 | жёсткий пол: ниже — приложение клампится и показывает предупреждение |

Порядок ужимания (сначала — наименее ценное): бренд → декор шага → метки чипов → доки в
рейлы → ряды консоли переносятся. **Доска не сжимается никогда** — она первая по приоритету.
Наблюдатель: журнал расширяется до 400px (F-57). Ни один контрол не уезжает за вьюпорт
ни на одном профиле (P-6, I-10) — это проверяет аудит размера в прототипе.

## 8. Голос интерфейса

- Действия — глаголами, caps: БРОСОК, КУПИТЬ $N, ОТКАЗ, СТАВКА, ПАСС, ОПЛАТИТЬ $N,
  КОНЕЦ ХОДА. Сумма — на самой кнопке.
- Клетки и события — словами («Cedar Ave», «Grand Place»), не номерами; без служебных
  тегов вида `[auction_bid]` в ленте (P-10).
- Один язык за раз: RU/EN переключаются живьём; композитные строки **пере-выводятся** из
  состояния, а не пере-переводятся по памяти (P-11).
- Ошибки — человеческим языком и с причиной: `Причина: …` из ответа движка (F-44).
- Честность: «Паузы нет — матч живёт по таймерам» (наблюдатель), «ожидание Neuro…» (SDK-место),
  второй SDK-слот подписан «играет как ИИ».

**Пять шагов внедрения (в этом порядке, каждый шаг не ломает предыдущий):**
1. **Токены** — добавить новые ключи во все скины + `tokens.json` как контракт. Гейт:
   `skin_probe` (полнота) + перенастроенный `compare_mockup.py` (палитра = значения).
2. **Роли текста** — закрепить фабрики в `theme.gd` (сделано) и запретить третью;
   гейт — проба цены раскладки (`label_cost_probe`) и ≥40 FPS в браузере.
3. **Каркас** — `game_view`/`layout_profile`: доки, рейлы, консоль; регионы из реестра
   получают `data-od-id`-эквиваленты (имена узлов = id реестра) — сверка структуры по реестру.
4. **Компоненты** — по одному: места → журнал → инспектор → консоль → модалки → оверлеи;
   после каждого — существующие пробы (p2/p3/p4) + новые точечные.
5. **Гейты** — новые поведенческие пробы (§ coverage), перф-бюджет `fps_clean.py` ≥40 median,
   и `check_package.py` в CI рядом с `board_test.gd`.

**Что гарантированно НЕ меняется при внедрении:** детерминизм (UI не мутирует состояние,
интенты через fail-closed `push_intent`), spectator-safe (только `for_spectator`), роли
выбираются при запуске, лицензионная чистота (оригинальные имена/арт/палитры), данные
(`board*.json`, `cards.json`) и цены. Дизайн — потребитель проекций, как и было.

**Почему дизайн переживёт будущие изменения:**
- всё, что видно, выражается токенами; новый скин = полный набор ключей, без правок кода;
- макет **генерируется из игры** (доска, строки, палитры) — изменить игру и пересобрать
  макет может один человек одной командой; рассинхрон ловится `check_package.py`;
- новые состояния — это данные + ключ + проба: сцены прототипа и раздел состояний спеки
  расширяются по образцу, без изменения системы;
- текстовый бюджет и роли зафиксированы машинно (аудит в прототипе → проба в игре) —
  будущие правки не смогут «незаметно» снова навязать перенос всем меткам (память о P-3).
