# Сверка результата с макетом

`tools/ci/compare_mockup.py` — сравнивает приложение с макетом **точно**, а не на глаз.

## Запуск

```sh
python tools/ci/compare_mockup.py neuro     # или: evil
```

Выход 0, когда палитра, пропорции колонок и структура совпадают с объявленным в макете.

## Что и как сравнивается

Макет — это не картинка, а **спецификация**, и он несёт свой дизайн в машиночитаемом виде.

| Ось | Макет объявляет | Приложение | Как сверяется |
|---|---|---|---|
| **Палитра** | `:root[data-theme="neuro"]` — `--tx`, `--ac`, `--bad` … | `skin.json` → `tokens.color` | по значению, Δ в единицах RGB |
| **Колонки** | `--L:272px`, `--R:330px` | измеряются по кадру | по **пропорции**, а не в пикселях |
| **Структура** | `top`, `mid`, `pl`, `stage`, `jr`, `act` | те же полосы в кадре | по наличию и порядку |

Пропорция, а не пиксели: приложение работает в 1440 px, макет рассчитан на другую ширину,
а адаптивная раскладка сохраняет **отношение**, не абсолют.

## Замер

```
палитра     11 из 11 токенов, Δ=0 (байт в байт)
колонки     макет 272/330 = 1.21   приложение 239/290 = 1.21
структура   6 из 6 регионов
```

## Чего здесь нет

**Попиксельного сравнения изображений.** Разные рендереры, шрифты, масштабы: такое
сравнение отметило бы различием всё и не сказало бы ничего. Сравнивается то, что
объявлено точно, — и это единственное, о чём можно утверждать что-либо твёрдо.

## Ошибки в самой пробе, найденные по ходу

**1. Имена токенов читались с дефисами.** Регулярка захватывала `--bg` вместо `bg`,
и все 11 сравнений давали «не найдено», хотя цвета совпадали точно.

**2. Границей панели считался `x=0`** — рамка окна, у которой нет поля с одной стороны.
Отсюда «ширина панели 0px». Теперь край — это тонкий штрих, у которого поле с **обеих**
сторон.

**3. Искались не те регионы.** Я искал `id="left"`, `id="board"`, а макет называет их
семантически: `pl` (игроки), `stage` (поле), `jr` (журнал).
