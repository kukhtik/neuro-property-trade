## 1. Жёсткие правила (нарушение = откат)

1. **Вердикт — только строкой вывода:** `ran N tests, 0 failed` / `ALL TESTS PASSED` /
   `==> ORACLE PASSED` / `==> ID PASSED/FAILED: причина`. Exit code — не вердикт (Godot
   падает при выходе; bash-обёртка возвращает 0 от `echo`). `SCRIPT ERROR:` — с двоеточием.
2. **Новый чек обязан падать при возврате дефекта** — негативная проверка прогоняется
   в том же коммите и попадает в отчёт.
3. **Код без живого потребителя не коммитится** (проверка — P0.2).
4. **Мёртвый код удаляется, не архивируется.** `archive/` — удалить целиком (git и есть архив).
5. **MIN_TESTS растёт только вместе с реальным тестом;** вниз — только с объяснением
   и планом возврата, тем же коммитом.
6. **Бюджеты:** проверки ≤ 40% кода продукта; доков — этот файл + один `state-*.md`.
7. **Артефакт = истина:** `dist/` и `build/current/` собираются из HEAD; дата артефакта ≥
   даты коммита. Perf — только `tools/fps_clean.py` на пустой машине; SG-10 первым в реестре.
8. **Сценарий = одна команда, вердикт строкой, ≤3 минут, на релизной сборке (web/exe).**
   Новые in-Godot гейты не добавлять; гейт — только вместо более слабой проверки.
9. **Читаемость — общая и постоянная (правило владельца, 16.10): никаких отдельных ролей,
   режимов и «эфирных» веток для масштаба текста.** Масштаб — свойство раскладки при данном
   разрешении, одинаковое для игрока, эфира и веба. Кегль не зависит от того, кто смотрит:
   зависит от размера картинки. Замер — на нативных больших разрешениях, а «видно ли с телефона»
   считается как эффективный кегль = кегль_в_кадре × (ширина_экрана / ширина_кадра).

### P1.1 — S3: измерения на артефакте · СДЕЛАНО (16.10) — сценарий красный ровно по телефону;
### замер «эфир → телефон» написан вечером (STREAM-READ, карантин)

Сценарий: `bash tools/ci/scenario_s3.sh` — одна команда, одна строка вердикта
`==> S3 PASSED/FAILED: причина` (все провалившиеся половины перечисляются через ` | `).
Две половины, потому что ни одна не честна в одиночку.

**A. Релизная сборка** (`tools/ci/s3_artifact.py`). Web-экспорт делается ЭТИМ прогоном
(`build/s3/web`, абсолютный путь; mtime `index.pck` сверяется со стартом), поднимается хост с
REMOTE-местом, Chromium открывает сборку как это место на 1280×720 и 390×844. Браузер отвечает
только на то, на что способен: сборка **дошла до матча** (ждём `JOINED pid=` из её собственной
консоли — по «непустому кадру» проходил ЗАГРУЗОЧНЫЙ ЭКРАН, 97% одной краски), `canvas == окно`
(±2px), документ не переполнен, ошибок консоли 0 (в allowlist ровно две строки вендорного
аддона `NEURO_SDK_WS_URL … not set` + стек-кадр этой же ошибки; любой другой стек валит), и
**покрытие палитрой** `token_coverage` (доля пикселей в Δ≤8 от токена скина; пол 0.90).

**B. Живое дерево** на тех же размерах: `game/tools/phone_fit_probe` (в git этим же шагом) и
READ-гейт (кегли + заполненность доков, печатает и 1280×720). Кегли и «вылезло за окно» браузеру
не видны — интерфейс рисуется в canvas, DOM пуст, — поэтому эти инварианты меряются ВНУТРИ
приложения, а не выдумываются из пикселей.

**Вердикт последнего прогона:**
```
S3 ART frame_1280x720 joined=True canvas=1280x720 colours=939  token_coverage=0.974 console_err=0 console_ignored=2
S3 ART frame_390x844  joined=True canvas=390x844  colours=652  token_coverage=0.972 console_err=0 console_ignored=2
==> S3 FAILED: ==> PHONE PROBE FAILED: 390x844: `…/@MarginContainer@5` leaves the viewport (rect [0,0 859x844] vs [0,0 390x844]) (299 total)
```
То есть артефакт снят и измерен (обе половины вердикта — числа), а красное ровно одно: **телефон**.
`root=390x844 audited=648 offscreen=299` — контент держит минимальную ширину **859px** в окне
390px (каскад начинается в `top/@HBoxContainer@8`, 815px): верхняя панель не сжимается и не
переносится. Это и есть следующий шаг S3 (не «переписать всё», а научить шапку узкому окну).

**Что нашлось при внедрении (и чем закрыто):**
1. **Регрессия, которую внёс я сам в P0.2** — `settings_overlay._validation_error` звал
   `get_item_text(r["token"]).selected` вместо `get_item_text(r["token"].selected)`. Оракул
   (388 тестов, `0 SCRIPT ERROR`) её **не поймал**; поймал READ-гейт:
   `SCRIPT ERROR: Invalid type in function 'get_item_text' in base 'OptionButton'`. Вывод этой
   сессии: путь валидации настроек набором не покрыт. Исправлено; после правки READ-01/02/03
   снова зелёные.
2. **Телефонная проба врала числами.** В одном прогоне 390×844 дала 0 находок, а 412×915 — 131:
   окно и раскладка ещё доезжали. В другом окно вообще не приняло размер (`root 1440x900` при
   запросе 390×844) — все числа описывали ДРУГОЕ окно. Теперь проба (а) переспрашивает размер,
   пока root его не примет, (б) ждёт двух одинаковых геометрических подписей подряд и
   (в) печатает `root=… audited=… offscreen=…`, а не «scanned»: «измерил ноль» больше нельзя
   спутать с «всё хорошо».

### P1.1-доп · находки 17.10: сетка интерфейса, глифы, блендинг

## 4а. Фаза 3 — ЭКОНОМИЯ РЕСУРСОВ (новая задача владельца, 23.10)

> «добавь новую задачу - оптимизация, хочу приблизится к качеству оптимизации игр из 2000 года,
> чтобы потребляли минимум ресурсов».

**ЧТО ЭТО ЗА ЦЕЛЬ.** Игры 2000 года не «оптимизировали» — они были **уже экономными**:
ассеты фиксированы, в кадре ничего не создаётся, память ограничена, а движок не умел того,
что умеет Godot 4 (дерево узлов, сцены, Resource, скриптовые объекты). Приблизиться к их
качеству = принести продуктту свойства, которые тогда были нормой, и **ЗАМЕРИТЬ** их, а не
почувствовать:

| Свойство | Что это значит на практике |
|---|---|
| **Ноль аллокаций в кадре** | в горячем пути не создаются ни массивы, ни словари, ни строки |
| **Нет поиска по дереву в кадре** | ни `get_node`, ни `find_child` в `_process`/`_draw` |
| **Нет строковых склеек в кадре** | ни `str()`, ни `%`, ни конкатенации в кадре |
| **Память не растёт** | ObjectDB стабилен на длинной партии, журнал ограничен |
| **Перерисовка по событию** | дерево интерфейса перерисовывается, когда изменилось состояние, а не каждый кадр |
| **В поставке нет того, что игра не использует** | ни тестового инструментария, ни неиспользуемых модулей; вес пакета — измеренная величина, а не «вроде легче» |

### 4а.1. ЖЁСТКОЕ ПРАВИЛО: обрезка не должна портить интерфейс и работу игры

> «если мы будем что-то заменять, то нельзя допускать падения user performance в качестве
> интерфейса или работы игры» (владелец, 23.10)

Значит **каждая** замена в этой фазе обязана доказывать, что качество не упало. Порядок
работы неизменен и обязателен:

1. **замерить «до»** (вес, время кадра, аллокации) — числа, не ощущения;
2. **изменить ОДНУ вещь**;
3. **прогнать гейты качества** — и все они должны остаться зелёными:
   * `MOCK-01` — визуал не развалился (живой кадр против эталона);
   * `MOCK-02` — визуальный вкус (кегль, потолок, роль не переопределена);
   * `SG-10` — плавность (fps двух сборок);
   * оракул — игра работает и не сломалась;
   * `S3` — собранный пак реально открывается в браузере и играется;
   * `ECO-01…ECO-05` — потребление не выросло.
4. **замерить «после»** и сравнить с «до».

**Правило отбора:** если вес упал, а хоть один гейт качества покраснел — **замена
отклоняется**, даже если цифры выглядят выгодно. Экономия не имеет права покупаться
качеством. Пример из этой же фазы: `res://tools/replay.gd` нельзя выкинуть «по списку
лишнего», потому что продукт грузит его в рантайме (`game/seats/seat_manager.gd:212`) —
выбросили бы работу игры.

### 4а.2. «Не нести лишнего» — что уже измерено (23.10)

**Пак (`.pck`) — то, что мы контролируем:**

| Что | Было | Стало | Как |
|---|---|---|---|
| вес пака | 1 074 960 B | **676 612 B** (−37,1 %) | `export_presets.cfg`: исключён CI-инструментарий |
| файлов в паке | 492 | **310** (−182) | то же |
| из них тестового инструментария | 132 (`res://tools/`) | **2** (`replay.gd` + его `.gdc`) | `tools/gates/*`, `tools/*_probe.gd`, `tools/*.tscn`, CLI-инструментарий |

**Проверка стала машинной:** `C3` в `acceptance_gate.sh` требует, чтобы в паке не было **ни
одного** файла `res://tools/`, кроме семейства `replay.gd`, **и** чтобы `replay.gd` в паке
**остался** (обрезка не должна съесть работу игры). Негатив проверен: на старом паке →
`==> ACCEPTANCE FAILED: 11 of 12 promises are met; 1 are open: C3` (найдено 132 лишних пути).

**Движок (`index.wasm`, 39 514 754 B) — то, что мы НЕ контролируем без отдельной сборки.**
Он в **58 раз** больше пака, и в нём лежат модули движка, которых игра не использует (3D,
часть модулей). Уменьшить его можно только **своим шаблоном экспорта** (сборка Godot из
исходников с отключёнными модулями) — это отдельная работа с отдельной оценкой риска, её
объём честно измерит `ECO-05`, а не «на глаз».

**ЧЕСТНОСТЬ ЧИСЕЛ.** 37 % — это пак, а не вся поставка. Полная загрузка web-сборки:
≈ 40,9 МБ (wasm 39,5 МБ + pck 1,07 МБ + js 0,28 МБ) → ≈ 40,5 МБ после обрезки, то есть
**−0,8 % трафика**. Настоящий выигрыш — не в трафике, а в том, что в руку игроку не уходит
инструментарий на 37 % веса пака; а настоящий рычаг трафика — свой шаблон экспорта
(`ECO-05`), и его размер честно неизвестен, пока не собран.

### 4а.4. КАРТОЧКИ ФАЗЫ 3 (контракты исполнителям; одна карта = одна сессия)

Каждая карточка — семь полей: **обещание** (что получит пользователь), **scope** (что можно
трогать), **do-not-touch** (что нельзя), **приёмка** (точная команда + ожидаемая строка
вердикта), **артефакт** (где лежит результат и как его открыть), **бюджет** (время/повторы),
**роль+модель**. Карта без любого поля не отправляется — чинится карта, а не исполнитель.
Правила: карты делятся **по файлам**, а не по теме; общие файлы (реестр гейтов, числа в
доках) — зона диспетчера; принимается карта **по дословной строке вердикта**; после цикла
решение пишется в журнал (дата, решение, причина, строка вердикта).

---

| Поле | Значение |

| **scope** | `game/tools/eco_budget_probe.gd` (заготовка есть), `tools/ci/eco_budget.py` (есть), `tools/ci/eco_budget.json` (бюджет — **не записан**), `tools/ci/gates/eco01_budget_gate.sh` (есть) |
| **do-not-touch** | продукт (`game/ui`, `game/core`, `game/seats`, `game/visual`) — на этом шаге не трогать; `tools/ci/run_gates.sh` (реестр — зона диспетчера); `docs/**` |

### 4а.5. ПРАВИЛА ФАЗЫ 3 (обязательны для всех карточек выше)

1. **Правило владельца:** заменить что-либо так, чтобы **не упало** качество интерфейса и
   работы игры. Значит: замерить «до» → изменить ОДНУ вещь → гейты качества (`MOCK-01`,
   `MOCK-02`, `SG-10`, оракул, `S3`) зелёные → замерить «после». Покраснело — **отклонить**.
2. **Храповик, а не «ноль терпеть».** Гейт, красный с первого дня, через неделю отключают.
   Число живёт в файле (`eco_hotpath_baseline.txt`, `eco_budget.json`), видно в diff, и может
   только убывать. Сейчас: горячий путь — **0**; бюджет кадра — **не записан**.
3. **Новый гейт начинается в карантине** (`docs/restoration/gates.md`): в `required` — после
   2–3 зелёных прогонов подряд.
4. **Оконные гейты (SG-03, SG-07, ECO-01) чувствительны к нагрузке на машине.** Красный
   оконный гейт сначала повторяется **изолированно**; если изолированно зелёный — это флейк
   нагрузки, и это пишется в журнал, а не замалчивается.
5. **Проверка — по продукту.** Строка в реестре, файл или ключ — это артефакт, а не обещание.
   Гейт, который не может покраснеть, не является гейтом.
6. **Правка реестра и чисел в доках — зона диспетчера**, не исполнителя (иначе карты
   перетирают друг друга: потерянное обновление, о котором никто не узнает).
