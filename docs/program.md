## 1. Жёсткие правила (нарушение = откат)

1. **Вердикт — только строкой вывода:** `ran N tests, 0 failed` / `ALL TESTS PASSED` /
   `==> ORACLE PASSED` / `==> ID PASSED/FAILED: причина`. Exit code — не вердикт (Godot
   падает при выходе; bash-обёртка возвращает 0 от `echo`). `SCRIPT ERROR:` — с двоеточием.
2. **Новый чек обязан падать при возврате дефекта** — негативная проверка прогоняется
   в том же коммите и попадает в отчёт.
3. **Код без живого потребителя не коммитится** (проверка — P0.2).
4. **Мёртвый код удаляется, не архивируется.** `archive/` — удалить целиком (git и есть архив).
5. **MIN_TESTS растёт только вместе с реальным тестом;** вниз — только с объяснением
   и планом возврата, тем же коммитом.
6. **Бюджеты:** проверки ≤ 40% кода продукта; доков — этот файл + один `state-*.md`.
7. **Артефакт = истина:** `dist/` и `build/current/` собираются из HEAD; дата артефакта ≥
   даты коммита. Perf — только `tools/fps_clean.py` на пустой машине; SG-10 первым в реестре.
8. **Сценарий = одна команда, вердикт строкой, ≤3 минут, на релизной сборке (web/exe).**
   Новые in-Godot гейты не добавлять; гейт — только вместо более слабой проверки.
9. **Читаемость — общая и постоянная (правило владельца, 16.10): никаких отдельных ролей,
   режимов и «эфирных» веток для масштаба текста.** Масштаб — свойство раскладки при данном
   разрешении, одинаковое для игрока, эфира и веба. Кегль не зависит от того, кто смотрит:
   зависит от размера картинки. Замер — на нативных больших разрешениях, а «видно ли с телефона»
   считается как эффективный кегль = кегль_в_кадре × (ширина_экрана / ширина_кадра).

### P1.1 — S3: измерения на артефакте · СДЕЛАНО (16.10) — сценарий красный ровно по телефону;
### замер «эфир → телефон» написан вечером (STREAM-READ, карантин)

Сценарий: `bash tools/ci/scenario_s3.sh` — одна команда, одна строка вердикта
`==> S3 PASSED/FAILED: причина` (все провалившиеся половины перечисляются через ` | `).
Две половины, потому что ни одна не честна в одиночку.

**A. Релизная сборка** (`tools/ci/s3_artifact.py`). Web-экспорт делается ЭТИМ прогоном
(`build/s3/web`, абсолютный путь; mtime `index.pck` сверяется со стартом), поднимается хост с
REMOTE-местом, Chromium открывает сборку как это место на 1280×720 и 390×844. Браузер отвечает
только на то, на что способен: сборка **дошла до матча** (ждём `JOINED pid=` из её собственной
консоли — по «непустому кадру» проходил ЗАГРУЗОЧНЫЙ ЭКРАН, 97% одной краски), `canvas == окно`
(±2px), документ не переполнен, ошибок консоли 0 (в allowlist ровно две строки вендорного
аддона `NEURO_SDK_WS_URL … not set` + стек-кадр этой же ошибки; любой другой стек валит), и
**покрытие палитрой** `token_coverage` (доля пикселей в Δ≤8 от токена скина; пол 0.90).

**B. Живое дерево** на тех же размерах: `game/tools/phone_fit_probe` (в git этим же шагом) и
READ-гейт (кегли + заполненность доков, печатает и 1280×720). Кегли и «вылезло за окно» браузеру
не видны — интерфейс рисуется в canvas, DOM пуст, — поэтому эти инварианты меряются ВНУТРИ
приложения, а не выдумываются из пикселей.

**Вердикт последнего прогона:**
```
S3 ART frame_1280x720 joined=True canvas=1280x720 colours=939  token_coverage=0.974 console_err=0 console_ignored=2
S3 ART frame_390x844  joined=True canvas=390x844  colours=652  token_coverage=0.972 console_err=0 console_ignored=2
==> S3 FAILED: ==> PHONE PROBE FAILED: 390x844: `…/@MarginContainer@5` leaves the viewport (rect [0,0 859x844] vs [0,0 390x844]) (299 total)
```
То есть артефакт снят и измерен (обе половины вердикта — числа), а красное ровно одно: **телефон**.
`root=390x844 audited=648 offscreen=299` — контент держит минимальную ширину **859px** в окне
390px (каскад начинается в `top/@HBoxContainer@8`, 815px): верхняя панель не сжимается и не
переносится. Это и есть следующий шаг S3 (не «переписать всё», а научить шапку узкому окну).

**Что нашлось при внедрении (и чем закрыто):**
1. **Регрессия, которую внёс я сам в P0.2** — `settings_overlay._validation_error` звал
   `get_item_text(r["token"]).selected` вместо `get_item_text(r["token"].selected)`. Оракул
   (388 тестов, `0 SCRIPT ERROR`) её **не поймал**; поймал READ-гейт:
   `SCRIPT ERROR: Invalid type in function 'get_item_text' in base 'OptionButton'`. Вывод этой
   сессии: путь валидации настроек набором не покрыт. Исправлено; после правки READ-01/02/03
   снова зелёные.
2. **Телефонная проба врала числами.** В одном прогоне 390×844 дала 0 находок, а 412×915 — 131:
   окно и раскладка ещё доезжали. В другом окно вообще не приняло размер (`root 1440x900` при
   запросе 390×844) — все числа описывали ДРУГОЕ окно. Теперь проба (а) переспрашивает размер,
   пока root его не примет, (б) ждёт двух одинаковых геометрических подписей подряд и
   (в) печатает `root=… audited=… offscreen=…`, а не «scanned»: «измерил ноль» больше нельзя
   спутать с «всё хорошо».
3. **Палитру на живом кадре по кластерам судить нельзя.** Число необъяснённых кластеров прыгало

**ПОПРАВКА ВЛАДЕЛЬЦА (16.10, после P1.1): «телефон» — это НЕ окно игры 390px.**
Смотреть эфир с телефона ≠ играть с телефона. Обещание S3 — про **картинку эфира в нативных
больших разрешениях**, которую зритель видит с телефона; никаких отдельных ролей для читаемости,
масштаб общий и всегда. Что из этого следует:

* половина B меряет **не то**: `phone_fit_probe` в окне 390×844 (299 находок, контент требует
  859px) — это про игру с телефона, чего продукт не обещает. Проба остаётся инструментом, но
  **из вердикта S3 выводится**;
* настоящая мера: кадр роли эфира на 1920×1080 (и выше) → эффективный кегль на телефоне =
  кегль_в_кадре × (390 / ширина_кадра) → пол для того, что зритель обязан понять с одного взгляда
  (чей ход, что происходит, деньги, заголовок журнала). Пример счёта: 14px в кадре 1920 дают
  ≈2,8px на телефоне — невидимо; чтобы получить 12px на телефоне, в кадре нужно ≈59px;
* **первый замер по существу, сделанный тут же:** `UiProfile.text_scale = 1.15` («крупнее для
  эфира») **не читает никто** — и это было невидимо сканеру потребителей, пока он считал запись
  использованием. Правило исправлено (запись ≠ потребитель), и сканер сразу показывает: ORPHAN
  `text_scale` (2 упоминания в комментариях), ORPHAN `data_source`, `header_full`,
  `shows_journal`, `shows_role_badge`. То есть отдельная роль эфира картинку не увеличивала
  вообще — удаляется вместе с идеей ролевого масштаба.

**Что НЕ проверено:** кегли внутри упакованной сборки (браузер их не видит: пока мерит гейт по
живому дереву; перенос измерения внутрь сборки — работа P2); сценарий не включён шагом
в CI (нужен python с playwright+PIL).

**Вердикт сегодня:** `==> STREAM-READ FAILED: the smallest glance label is 2.0px on a phone
(what is happening (the phase): 10px in the 1920x1080 frame) - below the 12px floor`. Это красное —
**правда обещания S3**, а не дефект гейта: проверено в обе стороны (пол 1.5 → PASSED, пол 12 →

**Что было попробовано и откачено** (в запись, чтобы не повторять): вшить пол в оболочку.
Рост кеглей шапки и журнала до пола на 1440×900 завалил SG-01 (`header height 166.0 != 56`) и

уменьшается ровно во столько раз, во сколько текст пришлось бы растить. «Читаемо с телефона» и
«нативное большое разрешение» тянут в разные стороны, и общий масштаб текста их не мирит:
**решение — за владельцем, здесь оно не угадывается.**

**Найдено этим замером (и исправлено тем же вечером, коммит `e3f54c2`):** в AI/autoplay-матче

напрямую и не отдавали `res["events"]` менеджеру, поэтому журнал, тосты и плашки на доске пусты
весь матч (это ровно то, что обещает S3 «видно, что происходит»). Числа: человеческий путь

проверка (вернуть прямой `submit_intent`) возвращает 0. **SG-06 был зелёным и слепым** к этому:
он гоняет матч через `push_intent`, то есть через работающий путь.

**Что НЕ проверено (обновлено):** кегли внутри упакованной сборки (перенос измерения внутрь —

### P1.1-доп · находки 17.10: сетка интерфейса, глифы, блендинг

Три вещи, которых ни оракул, ни гейты не видели, и как они ищутся теперь. Общий урок: **кадрами
ревьюить дороже и слабее, чем деревом** — все три нашлись одним дампом прямоугольников живого
дерева за 5 минут, тогда как дни разглядывания скриншотов их пропустили.

1. **Каждая клетка рисовала лицо ДВАЖДЫ.** `tile_view._build` вешал
   `set_anchors_preset(PRESET_FULL_RECT)` (Control сам заполняет родителя), и `_layout_children`
   ТАМ ЖЕ ставил `_face.position/size`. Два механизма спорили: замер — клетка 95×95, лицо
   186×186, на всех 40 клетках. Это и есть «клетки по две» владельца. Правило: **у прямоугольника
   один хозяин** — раскладка.
2. **Панели были раскрыты ровно там, где доске нужна ширина.** Порог рейлов висел на
   `is_compact()`, а `RAILS_BELOW` — константа, заведённая ровно для этого — не читалась ничем.
   Доска квадратная, значит её размер = `min(колонка, высота)`, и узкая колонка отнимает у кольца
   напрямую: 1600×1200 давало кольцо 972px при открытых панелях и 1048px при рейлах, а 1280×720
   с открытыми панелями — 620px, **хуже, чем окно 880px**. Теперь рейлы ниже 2000px.
3. **74 глифа рисовались квадратиками.** Продукт использовал 29 символов, шрифт имеет 6.
   Все пиктограммы и почти все стрелки/знаки давали missing-glyph box — на экране коробка там,
   где кнопка. **Выглядит как намеренная иконка**, поэтому кадрами не ловится: `Label` с текстом
   есть, дерево чистое. Закрыто гейтом `GLYPH`, который спрашивает `has_char` у того же шрифта,
   которым рисуют экраны.

**Два числа, которыми управляется вся сетка** (`game/ui/core/layout_profile.gd`, один дом):
`screen := Vector2i(1600, 1200)` — окно запуска (доска ограничена ВЫСОТОЙ: 900 даёт кольцо 748px
и имена 11px, 1200 — 1048px и 15px), и `RAILS_BELOW := 2000` — порог автосворачивания панелей.
Размер окна жил в ЧЕТЫРЁХ файлах (`main.gd`, `layout_profile.gd`, `sg07_capture.gd`,
`shots_report.py`); подняв один, получил SG-07 красным с «1600x1200, the profile promises
1440x900» — гейт поймал второй дом корректно. Теперь читают все четверо.
