## 1. Жёсткие правила (нарушение = откат)

1. **Вердикт — только строкой вывода:** `ran N tests, 0 failed` / `ALL TESTS PASSED` /
   `==> ORACLE PASSED` / `==> ID PASSED/FAILED: причина`. Exit code — не вердикт (Godot
   падает при выходе; bash-обёртка возвращает 0 от `echo`). `SCRIPT ERROR:` — с двоеточием.
2. **Новый чек обязан падать при возврате дефекта** — негативная проверка прогоняется
   в том же коммите и попадает в отчёт.
3. **Код без живого потребителя не коммитится** (проверка — P0.2).
4. **Мёртвый код удаляется, не архивируется.** `archive/` — удалить целиком (git и есть архив).
5. **MIN_TESTS растёт только вместе с реальным тестом;** вниз — только с объяснением
   и планом возврата, тем же коммитом.
6. **Бюджеты:** проверки ≤ 40% кода продукта; доков — этот файл + один `state-*.md`.
7. **Артефакт = истина:** `dist/` и `build/current/` собираются из HEAD; дата артефакта ≥
   даты коммита. Perf — только `tools/fps_clean.py` на пустой машине; SG-10 первым в реестре.
8. **Сценарий = одна команда, вердикт строкой, ≤3 минут, на релизной сборке (web/exe).**
   Новые in-Godot гейты не добавлять; гейт — только вместо более слабой проверки.

## 5. Как работать (протокол сессии и субагентов)

**Старт сессии (первые 10 минут):**
1. `skill_view('monopoly-dev')` — ловушки окружения (heredoc, MSYS-пути, `$(tools/ci/godot_bin.sh)`,
   веб-экспорт только абсолютным путём, вердикты строками).
2. Прочитать этот файл и `docs/restoration/gates.md` (реестр гейтов).
3. Снять живые числа: `bash tools/ci/run_tests.sh` (~2 мин), при необходимости `run_probes.sh`.

**Субагенты:**
- Максимум 2 параллельных (лимит). Ребёнок знает только свой контекст: давать путь репо,
  точные команды, дисциплину вердиктов, требование «respond in Russian» и схему отчёта
  (файлы / команды / вердикт-строки / блокеры).
- Доверять: механические переносы с замороженным интерфейсом (экран → `.tscn` с сохранением
  id и поведения), независимые проверки, research (IRC Твича, re-vendoring SDK).
- НЕ доверять: решения критического пути, коммиты (закрывает родитель), негативные проверки
  (родитель), всё, где нужно слово владельца.
- Отчёт ребёнка — самоотчёт: родитель повторяет ключевой прогон до коммита. Два провала —
  родитель делает сам.

**Отчёт владельцу (каждая сессия):** вердикты строками (оракул/сценарии), список файлов,
негативные проверки, что НЕ проверено. Без «зелено по памяти».
