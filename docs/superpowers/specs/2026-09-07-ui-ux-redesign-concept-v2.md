## 0. Резюме — пять ключевых решений

1. **Отдельного экрана «лобби» больше нет.** Приложение — ОДИН игровой экран.
   При запуске доска видна сразу (предматчевое состояние), поверх неё открыт
   оверлей «Настройки матча» с большой кнопкой СТАРТ. После старта тот же
   оверлей = внутриигровые настройки (часть полей применяется живьём, часть —
   «потребует рестарт»). Ответ на вопрос «зачем лобби отдельно» — незачем.
2. **Доска — главный герой.** Доска по умолчанию ВСЕГДА показывается целиком
   (полное кольцо, вписано в центр). «Кинокамера» (spectacle-панорамирование)
   — опциональный режим, по умолчанию выключен: сейчас камера режет кольцо и
   это главная причина «непонятно, где кто».
3. **Центр доски — сцена.** Пустой центр заполняется: бросок кубиков (анимация
   в стиле BG3), карточка текущего решения (покупка/аукцион), финальный баннер.
   Кубики переносятся из гипотетического угла панели в центр доски.
4. **Один источник цвета игрока.** Сейчас 4 разных массива цветов (seat_config,
   lobby, board_view, tile_view) — маркер владельца на клетке может НЕ совпадать
   с реальным цветом фишки. Вводится `PlayerIdentity` (цвет + token_id + имя)
   и всё читает только его.
5. **Все 17 проблем закрыты фазами P0–P5** (раздел 11), каждая фаза имеет
   поведенческие пробы (probe), а не скриншоты (llvmpipe-скриншоты ненадёжны —
   доказано на фазе A).

## 2. Общая концепция и структура экранов

### 2.1 Один экран + оверлеи

```
ПРИЛОЖЕНИЕ = GameView (всегда корневой визуальный слой)
Оверлеи (pop-up поверх, доска продолжает жить):
  ├ Настройки матча (⇄ бывшее лобби)   F1
  ├ Правила (динамические)             F2
  ├ Модалки решений: торг / ответ на торг / аукцион / стройка-залог
  ├ Подтверждение рестарта             F3
  ├ Итоги партии (победа/банкротства)
  └ Админ-консоль (host-only)          F12
Немые слои (не блокируют ввод, если не модальные):
  ├ Тосты (верх-центр, стек ≤3)
  ├ Баннер-события (крупные: покупка, аукцион, банкротство)
  ├ Кубики (центр доски, некликабельны)
  └ Подсказка выбранного тайла (инспектор, докнут в правую панель)
```

### 2.2 Жизненный цикл
```
ЗАПУСК → GameView + предматчевая доска (все фишки на GO, дефолтные 4 места:
Host LOCAL + 3 AI) + открытый оверлей «Настройки матча» (фокус на СТАРТ).
  СТАРТ  → оверлей закрывается, seat_manager стартует, игра идёт.
  ESC    → оверлей закрывается БЕЗ старта: доска в «холодном» состоянии,
           в панели действий одна кнопка «▶ НАЧАТЬ ПАРТИЮ» (открывает оверлей).
В ИГРЕ  → ⚙ открывает тот же оверлей: вкладки «Интерфейс/Звук/Язык» применяются
          живьём; вкладки «Игроки/Правила/Темп» помечаются «→ нужен рестарт»,
          кнопка «Применить: новая партия» (подтверждение) пересобирает движок.
КОНЕЦ   → баннер итогов (победитель, ходов, капитал) + [Реванш] [Настройки].
```

### 2.2.1 Ответ на вопрос про стартовое меню (явно)
**Отдельное меню НЕ нужно.** Аргументы:
- Настройки нужны ВО ВРЕМЯ партии (таймеры, агрессия ИИ, звук, язык) —
  отдельный экран делает их недостижимыми без рестарта.
- Стример не может позволить себе «переключиться в лобби» в прямом эфире.
- Быстрый старт не требует экрана: дефолты уже выбраны, СТАРТ — одна кнопка
  (Enter). Отдельный экран лишь добавляет клик.
- Единственная функция лобби, которой нужен «режим без игры», — правка состава
  игроков до старта. Это решается тем, что до старта оверлей открыт сам, а
  доска за ним — живой предпросмотр (видно, как выглядят цвета/фишки).

Миграция: `lobby.gd` → `settings_overlay.gd` (переиспользуем редактор строк
мест), `main.gd` сразу строит GameView; движок создаётся лениво при СТАРТ.

- TopBar 44px: слева логотип; центр — чип хода (мини-фишка + имя + фаза

уменьшаются. Доска остаётся целым кольцом.

### 3.3 Узкий/низкий режим <1024 (включая WebGL-встройку)
Обе боковые панели → выдвижные оверлеи; панель действий → «лист снизу»

используется в браузере-зрители (WebGL-сборка остаётся read-only наблюдением).

## 4. Клетки и фишки

### 4.1 PlayerIdentity — единый источник (обязательный рефакторинг-фундамент)
```
core/player_identity.gd (новый, статический):
  colors[i] → 8 контрастных на #16191f:
    #e0524a #4fa3e0 #4fbf74 #e8c545 #a86ee0 #e58a3c #46c8b8 #d46a9e
  token_for(i) → "ship|top_hat|dog|cat|race_car|boot|iron|wheelbarrow"
  color_of(seat) / token_of(seat) — единственная точка, где берутся цвета.
```
Потребители: tile_view (рамка владельца), token_panel (гало+спрайт),
players_panel (аватар), top_bar (чип хода), event_messages (цвет имени в
журнале/тостах). Массивы-дубликаты в lobby/board_view/tile_view удаляются.
Новый плеер = следующий свободный цвет/фишка (никогда не повторяются в матче).

### 4.2 Анатомия клетки (клетка = cell px, всё пропорционально)
```
        КЛЕТКА (базовый фон — assets/tile.svg, тёмный #20252f, светлый текст)
 ┌──────────────────────────────────┐
 │ ▓▓▓▓▓▓▓▓▓▓ ГРУППА ▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │ ← полоса группы на грани К ЦЕНТРУ (28% cell)
 │  🏠🏠🏠🏠  или  🏨                │ ← домики: assets/houses/*.svg НА полосе
 │                                  │
 │        Лесной проспект           │ ← имя: до 2 строк, авто-fit 9..13px
 │                                  │
 │            $100                  │ ← цена (низ)
 └──────────────────────────────────┘
   рамка 2px цветом владельца по периметру + круг-бейдж ⌀12px с инициалом
   владельца в УГЛУ У ВНЕШНЕГО края; залог: клетка обесцвечивается (sat 0.35)
   + диагональная штриховка 20% + бейдж владельца тускнеет
```
Решения и почему:
- **Группа** — всегда родной цвет группы (палитра `visual/theme.gd` остаётся:
  она оригинальная, не-Hasbro). Владелец НЕ смешивается с группой (v1 предлагал
  lerp — на малых клетках цвета сливаются); владелец = рамка + бейдж. Рамка
  видна на любом масштабе, группа остаётся опознаваемой.
- **Имя**: в `board.json` добавляется поле `"short"` (короткое имя ≤14 симв.,
  отдельный коммит данных). Правило рендера: если cell ≥ 44 → до 2 строк
  (autowrap, шрифт auto-shrink 13→9); если cell < 44 (compact) → 1 строка с
  ellipsis по `short`. Это убирает «Lake Dr…» без потери точных названий.
- **Иконки**: углы — `assets/corner_icons/*.svg` (крупно, центр, база слегка
  тонируется цветом типа); типы — `assets/type_icons/*.svg` вместо юникода.
- **Компакт-режим** (cell < 44): цена скрыта, домики → бейдж «×N»/«H», имя 1
  строка. Порог читаемости: полный режим требует cell ≥ 44; при 1440×900
  cell ≈ 58–71 (уже достижимо после сжатия боковых панелей).
- **Подсветки**: активный тайл = светящаяся рамка акцента (#4fb3d9, 2px,
  пульс 0.8 Гц) — вместо modulate; выбранный инспектором = пунктирная рамка
  цвета акцента; валидные цели менеджмент-действия (стройка/залог) = мягкая
  заливка 12% поверх (кандидаты вычисляются из проекции; точный арбитр —
  движок, отказ приходит тостом с human-причиной).

### 4.3 Фишки
- Спрайт `assets/tokens/<token_id>.svg` (TextureRect), размер 0.38×cell
  (мин 20px), БЕЗ перекраски арта; под фишкой — цветное гало-круг
  (радиус 0.52×фишки, цвет PlayerIdentity) — цвет читается, арт остаётся
  чистым. Инициал не нужен (арт уникален), но в компакт-режиме поверх гало
  рисуется инициал.
- **Стоянка**: фишки на одной клетке расходятся веером по дуге 60° вокруг
  центра клетки (радиус 0.35×cell), z-order по pid; активный игрок — лёгкое
  покачивание (bob 1 Гц).
- **Движение**: пошаговая анимация по кольцу (интерполяция pixel_pos между
  соседними клетками, 70 мс/клетка, ease-in-out) — фишка «идёт», а не
  телепортируется; проход через GO — золотая вспышка. Дубли: короткий доп.
  прыжок. Тюрьма: фишка ставится за решётку угла (смещение к центру угла).
- Все анимации гасятся `settings.animations=false` → мгновенные позиции.

### 4.4 Карточка игрока (левая панель)
```
┌────────────────────────────────┐
│ (🐙) Host            [$ 1500]  │ ← фишка-аватар в гало цвета; имя цветом
│  @ «Большая шишка» · 9 тайлов  │ ← позиция НАЗВАНИЕМ клетки (не «@11»)
│  🏠 3   💼 1   ⚖ вых.: 1 карта │ ← дома, залоги, карта выхода
└────────────────────────────────┘
   активный ход: рамка акцента + ▶; тюрьма: бейдж ⚖ с числом попыток;
   away: серый + «авто-пас»; банкрот: зачёркнут, приглушён.
```
Тултип строки: полный свод (драйвер, деньги, позиция, тайлы по группам).
Клик по строке → камера/доска мягко подсвечивает клетку игрока. Слова «нед.»
не существует — только развёрнутые подписи.

## 6. Тултипы / уведомления / таймер / кубики

### 6.1 Тултипы (покрытие — закон, не пожелание)
- Стиль единый в `ui/theme.gd`: тёмный бокс #0d1117, рамка-акцент, 12px,
  отступ 8, задержка 350 мс.
- **Автопроба**: обход построенного UI-дерева, для каждого Button /
  OptionButton / CheckButton / SpinBox / LineEdit assert `tooltip_text != ""`.
  Проба включается в ui_smoke — тултипы больше не могут «забыться».
- Тултипы тайлов (2 строки: «Лесной проспект · коричневая группа · $100» /
  «владелец: Host · 🏠2 · аренда $30») и фишек («Host · LOCAL · $1500»).
- Формат: `[действие] — [что произойдёт] — [горячая клавиша, если есть]`.

### 6.2 Тосты и баннеры (уведомления посреди экрана)
- Источник: `engine.log.event_appended` → `EventMessages.describe`
  (апгрейд: имена клеток вместо номеров, локализация, цвет имени игрока).
- Тосты: верх-центр (на 8px ниже TopBar), стек ≤3, ширина ≤ 46% экрана:
  `info` 4 с · `success` 4 с · `warning` 6 с · `danger` 6 с · `auction`
  живёт, пока аукцион активен (клик → фокус на карточку аукциона).
  Анимация: slide-down + fade 200 мс / fade-out 300 мс.
- Анти-спам: рента/платежи одного хода сливаются в строку
  «Neuro платит $48: рента Host ×2, налог $20».
- Баннеры (крупные, по центру над центром-сценой, 1 шт, 2.5 с): покупка,
  старт аукциона, «дубль!», банкротство, победа, «Neuro уходит в тюрьму».
- Режим наблюдателя не отключает тосты (это главный канал для зрителя).

### 6.3 Таймер
- Кольцо 36px в TopBar рядом с чипом хода + цифры; данные: `holder` +
  `seat.decision_waiting` + окно (`turn_timer`/`auction_timer`) — менеджер уже
  отдаёт это в `state_changed` (добавить поля в emit_spectator-словарь).
- Цвет: >60 % зелёный → 30–60 % жёлтый → <30 % красный + пульс + тик-звук
  каждые 5 с на последней трети.
- Правила честности: окно = 0 → таймер скрыт; ход SDK-места — таймер скрыт,
  вместо него статус «ожидание Neuro…» (SDK-места принципиально вне
  менеджерского тайм-аута — не ломать!).
- Отдельный крупный отсчёт — на карточке аукциона в центре-сцене.

### 6.4 Кубики (центр-сцена, в стиле BG3, ~1.1–1.3 с)
```
ФАЗЫ:  spawn 0–0.15  (появление scale 0.6→1.0, fade-in)
       roll  0.15–0.7 (оба куба: парабола вверх, вращение 720°, тени)
       bounce 0.7–0.95 (2 приземления со squash: scaleY 1→0.75→1)
       settle 0.95–1.1 (доворот «лицом», короткая вспышка рамки)
       result 1.1+ (крупная сумма «8» над кубами 0.6 с; дубль — золотая
                    рамка + чип «ДУБЛЬ»; 3-й дубль — штамп «→ ТЮРЬМА»)
```
- Текстуры: `assets/dice/die_1..6.svg` (TextureRect), поворот через tween
  `rotation`+`scale`; выключенные анимации → мгновенный показ результата 0.8 с.
- События: кубики слушают `roll` из лога (d1/d2 уже в данных события).
- Мини-отображение последнего броска остаётся в панели действий (мелко).
- Звук: whoosh на roll, клик на каждый bounce (sfx.gd, процедурно).

## 7. Режим наблюдателя

- **Механика:** нет отдельного «режима» — есть матч, в котором нет LOCAL-места.
  Настройки: «Роль хоста: только наблюдаю» → все места AI/CHAT/SDK.
  `game_view` сам переходит в наблюдательную компоновку, когда `_human_pid == -1`.
- **Компоновка:** панель действий → тонкий статус-бар («ход Neuro · аукцион ·
  авто-через 0:08»); игроки — сворачиваемый рельс; журнал — расширен (правая
  панель 380px, 100+ строк, фильтры: игрок/тип/деньги); инспектор по ховеру;
  доска — во весь центр; тосты включены; кнопка 👁 меняется на «вернуться в
  настройки».
- **Управление зрителя:** клик по игроку/фишке — следить за ним (подсветка его
  клеток при наведении на строку), фильтр журнала, паузы НЕТ (движок не
  поддерживает паузу; тайм-ауты двигают игру — честно указать в UI:
  «пауза недоступна, матч живёт по таймерам»).
- Вход также из игры: кнопка 👁 доступна только если хост не сидит за LOCAL
  (иначе она бы «отключала» живого игрока).

## 8. Админ-панель (только хост, F12)

### 8.1 Доступ
- Флаг `is_host`: вычисляется в main.gd — `not OS.has_feature("web")` И
  отсутствие CLI-флага `--spectator`. На WebGL панель НЕ создаётся вообще и
  подсказка «F12 — админ» не рендерится (сейчас подсказка видна всем).
- Токен: существующий `admin_gate` сохраняется; пустой токен = локальный
  незащищённый режим (текущее поведение), непустой = запрос токена при первом
  открытии панели.

### 8.2 Переработка панели (понятность)
```

│ │ сводка: фаза · чей ход · у кого ожидание · чей таймер горит       │  │
│ │ [копировать JSON-дамп] [снапшот → файл] [загрузить снапшот]       │  │
│ ├ События ─────────────────────────────────────────────────────────┤  │
│ │ фильтр: [тип▼][игрок▼][тайл▼]   экспорт .jsonl   лента live       │  │

│ │ 📍 телепорт    pid▼ [1]  клетка [12▼ названия]       [Применить] │  │
```

- Неактуальные поля для операции скрыты (сейчас 6 SpinBox всегда на экране);
  у каждой операции описание-тултип («что делает, когда применять»).
- Результат операции — инлайн (ok / причина), плюс строка в журнал админа.
- Деструктивные операции (переиграть ход, порядок, снапшот-загрузка) — с
  подтверждением. Все правки по-прежнему идут через `admin_override` +
  event log (инвариант движка не трогаем).
- Локализуется вместе с UI; поисковый фильтр по операциям (🔍).

## 9. Локализация (RU сейчас, EN — полной заменой строк)

- `game/i18n/i18n.gd`: статический словарь `KEY -> {"ru": …, "en": …}` +
  `tr(key, vars={})` + сигнал `locale_changed`. Выбор CSV vs dict — dict:
  тестится headless без импорта переводов.
- Правила ключей: `ui.*` (кнопки/панели), `action.*` (действия из
  legal_actions), `phase.*` (человекочитаемые фазы вместо enum),
  `tile.<type>.*`, `toast.*`, `rules.*` (шаблоны с подстановками),
  `settings.*`, `admin.*`. Оценка объёма: ~180 ключей.
- `EventMessages.describe(entry, locale)` — журналы, тосты и баннеры на
  обоих языках (имена клеток берутся из board.json — они уже «свои»).
- Переключение языка в настройках (вкладка «Интерфейс») — мгновенно:
  сигнал `locale_changed` → все панели перечитывают тексты (перестроение
  текстовых label'ов, без пересоздания дерева).
- Правила-модалка собирается из локализованных шаблонов + фактических
  значений настроек (числа не переводим, `$` остаётся).
- Шрифт: дефолтный шрифт Godot содержит кириллицу — отдельный шрифт не нужен;
  проверить перенос строк RU (длиннее EN) в кнопках панели действий
  (минимальная ширина кнопки + ellipsis-защита).

## 10. Адаптивность

- Растяжение: `stretch mode = canvas_items`, базовое разрешение 1440×900,
  `aspect = expand` — на WebGL-встройке любого размера UI масштабируется
  линейно, а поверх этого работают точки останова из 3.4 (перекладка панелей).
- Доска: механизм A1 (пересчёт cell из фрейма + rebuild) сохраняется; новое
  правило — **фрустум всегда вмещает весь грид 11×11** (cell = min(w,h)/11),
  панорама spectacle выключена по умолчанию; при cell < 44 включается компакт.
- Минимальный поддерживаемый размер 900×600 (далее — предупреждение-тост
  «слишком узкое окно»).
- Пробы на 5 разрешениях (1440×900, 1280×720, 1024×640, 900×600, 1920×1080):
  assert cell уместился, панели в своих точках, ни один Control не выходит за
  вьюпорт (обход дерева: `global_rect` внутри `visible_rect`).
