# Neuro Property Trade — UI/UX-концепция полной переработки

> Документ-концепция для переписи интерфейса. Движок (engine, seat_manager,
> projection.for_spectator) не трогаем — только UI-слой (`game/ui/`, `game/visual/`),
> `game_settings.gd` (поля уже есть) и расширение event-log. Все ассеты уже лежат в
> `game/assets/` и импортированы Godot'ом — задача: **подключить их и перестроить
> компоновку**. Окно 1280×720 (рабочий минимум), тёмная тема, язык RU + EN.

---

## 0. Главный диагноз (почему сейчас «плохо выглядит»)

Один корневой дефект объясняет 80% жалоб:

**Готовые SVG-ассеты не используются. Весь визуал нарисован кодом через
`ColorRect`/`Label`** (`tile_view.gd`, `token_panel.gd`, `board_view.gd`).

- Клетки — светлые прямоугольники `#f0efe9` на тёмном фоне `#101820` → «светлая
  доска в тёмном окне», диссонанс с тёмной темой. Ассет `tile.svg` (тёмная
  гравюра с рамкой) лежит в `assets/` и не подключён.
- Фишки — цветные квадратики с инициалом. Ассеты 8 уникальных фигурок
  (ship, top_hat, dog, cat, race_car, boot, iron, wheelbarrow) лежат в
  `assets/tokens/` и не подключены.
- Кубиков нет вообще — бросок не визуализируется. Ассеты `die_1..6.svg` лежат в
  `assets/dice/`.
- Центр доски — пустая тёмная дыра. Ассет `board_center.svg` (фон с концентрическими
  кольцами) лежит в `assets/` и не подключён.
- Кнопки — `StyleBoxFlat`. Ассет `button.svg` (тёмная гравюра с голубой рамкой)
  не подключён.

Поэтому доска выглядит как «чёрновик», а не как игра. **Фаза G (подключение
ассетов) — это не «полировка», это фундамент.** Без неё вся остальная
переработка висит в воздухе.

## 1. Критический разбор текущего UX/UI

### 1.1. Клетки (tile_view.gd)
| Проблема | Где видно | Причина в коде |
|---|---|---|
| Светлые клетки на тёмном фоне, «плывут» | все скриншоты | `_base.color = Color("f0efe9")` — не тёмная тема |
| Имена обрезаются «…» почти везде | `ui_small.png`, `ui_played.png` | `_name.autowrap_mode = OFF` + `OVERRUN_TRIM_ELLIPSIS`, шрифт `cell*0.20` — при cell=48 имя «Garden Grove» не влезает |
| Текст «наезжает» / минимальный padding | `ui_game.png` | name/price/owner/houses все в одной клетке 64px, нет зон |
| Владелец = квадратик 8×8 в углу | `ui_played.png` | `_owner_marker` 8×8 — почти невидим |
| Домики = зелёные квадратики 5×5 | `ui_played.png` | `ColorRect` вместо `house.svg` |
| Иконки — юникод-глифы (🚂 ⚡ ₽ ✉ ?) | все | `TYPE_ICONS` — текстовые, рендерятся криво/разными шрифтами, а SVG-иконки лежат в `assets/type_icons/` |
| Активная клетка — `modulate 1.25` | — | почти не видно, нет glow/рамки |

### 1.2. Фишки (token_panel.gd)
- Квадратик с инициалом, а не фигурка. Ассеты 8 уникальных токенов не подключены.
- Все фишки стоят в **одном углу клетки** (`_corner_of` → top-left + offset 2,2) →
  при 2–4 игроках на клетке слипаются в кучу, перекрывают имя/цену.
- Нет связи «фишка = игрок» в панелях (в players_panel цвет, на доске — квадратик).

### 1.3. Композиция игрового экрана (game_view.gd)
- Слева players (12% ширины), справа journal (14%), между — доска. На 1280px доска
  сжимается до ~900px → cell ≈ 48px → обрезки имён.
- **Центр доски — мёртвая зона** (5×5 клеток пустоты). Не используется ни для
  чего, хотя туда должны идти кубики, уведомления, текущий ход.
- Journal справа (180px) и EventOverlay (432×202, bottom-right) **дублируют друг
  друга** — два лога событий на одном экране.
- TileInspector (360×90, bottom-left) наезжает на левую часть action-панели.

### 1.4. Верхняя полоса (top_bar.gd)
- Только: заголовок + «ХОД: X» + «ФАЗА: Y» + ⚙ + «F12 — админ».
- **Нет таймера** (требование №12). Нет кнопки правил (№7), нет рестарта (№10),
  нет меню настроек из игры (№10).
- «F12 — админ» виден **всегда**, в т.ч. на webgl, где админки нет (требование №14).

### 1.5. Нижняя панель действий (action_panel.gd)
- Кнопки обрезаются слева на узком окне (`ui_game.png`: «ПРОСИТЬ…», «СЕТТЛМЕНТ»
  частично за краем).
- Нет иконок, нет визуального разделения «первичное действие» (roll/buy) от
  вторичных (build/mortgage/trade).
- Статус-строка и hint — мелкий серый текст, легко пропустить.

### 1.6. Лобби (lobby.gd)
- Отдельный экран «до игры» — вопрос пользователя №1. Настройки (капитал, GO,
  тюрьма, дубли, залог, торги, агрессия ИИ) **не вынесены** — только таймеры,
  free_parking, порядок, язык, аукционы.
- Сетка настроек «лесенкой» (4/3/2 элемента), правый край обрезан.
- Нет выбора фишки (только цвет-свотч), нет выбора пресета доски.

### 1.7. Наблюдатель / логирование
- Хост не может быть наблюдателем (seat_config: seat 0 всегда LOCAL).
- Журнал 10 строк, без фильтра, без `ai_decision` (не видно, что думает ИИ).
- EventMessages на английском («p2 moves → 4») при RU-интерфейсе.

### 1.8. Админка (admin_panel.gd)
- Видна у всех, кто нажал F12 (нет `is_host`-гейта на UI-уровне, только token).
- Надпись «F12 — админ» в топбаре видна и на webgl.
- Нет тултипов к операциям, нет заголовка-подсказки, параметры — голые SpinBox'ы
  без контекста (pid/tile/amount всегда все видны, хотя нужны не все).

### 1.9. Локализация
- `settings.language` хранится, но **не подключён к строкам** — весь UI на RU
  хардкодом. EN отсутствует.

### 1.10. Адаптивность
- Доска масштабируется (cell 24–72), но при сжатии имена обрезаются, а не
  перестраиваются. Панели фиксированной пропорции, не сворачиваются.

## 2. Общая концепция и структура экранов

### 2.1. Ключевое решение: **один экран, лобби = оверлей**

Отвечаю на вопрос №1 напрямую: **отдельный экран лобби не нужен.**

Причина: лобби сейчас — это просто форма настроек. Доска не зависит от настроек
(она рисуется из `board.json`), поэтому **доску можно показать сразу**, а
настройки — как **оверлей-панель поверх доски** (как в Baldur's Gate 3: меню
настройки поверх мира, а не отдельный экран).

**Структура — один `GameView`, два состояния:**

```
┌──────────────────────────────────────────────────────────────┐
│  GAME VIEW (единственный экран)                              │
│                                                              │
│   Состояние SETUP  →  доска видна (дефолты) + оверлей        │
│                       «НАСТРОЙКИ ПАРТИИ» (полупрозрачный)    │
│                                                              │
│   Состояние PLAYING → оверлей снят, игра идёт                │
│                                                              │
│   Настройки/правила/рестарт → оверлей снова поверх игры      │
└──────────────────────────────────────────────────────────────┘
```

- **Старт:** приложение открывается сразу в `GameView` с доской (дефолтные
  настройки: 4 игрока, LOCAL+3×AI, 1500$). Поверх — оверлей настроек. Кнопка
  «▶ ИГРАТЬ» снимает оверлей и запускает движок.
- **В игре:** кнопка ⚙ в топбаре открывает тот же оверлей (настройки + правила +
  рестарт + меню). Доска видна за оверлеем (приглушена).
- **Плюс:** нет «пустого» лобби, настройки всегда под рукой, доска — живой фон
  (можно крутить настройки, глядя на доску).
- **Минус (риск):** движок создаётся только при «ИГРАТЬ». До этого доска —
  статичный предпросмотр (без движка). Это нормально: `BoardView.build()` уже
  работает без движка.

> Альтернатива (если хочется «как сейчас»): оставить лобби отдельным, но сделать
> его оверлеем на той же сцене (не менять сцену, а показывать/скрывать панель).
> Рекомендую первый вариант — он чище и отвечает на «зачем лобби отдельно».

### 2.2. Иерархия информации (что где и какого веса)

```
УРОВЕНЬ 1 (глаз всегда):  доска + фишки + активная клетка + текущий ход
УРОВЕНЬ 2 (по ситуации):  таймер, кнопки действий, уведомления по центру
УРОВЕНЬ 3 (справка):      players-panel, journal, tile-inspector
УРОВЕНЬ 4 (по запросу):   настройки, правила, админка
```

Правило: **всё, что не уровень 1, — сворачивается/приглушается**, чтобы доска
осталась главным объектом.

### 2.3. Навигация (одна карта)

```
[GameView]
  ├─ Топбар:  ⏱таймер | ХОД:Имя | ФАЗА | [⚙] [📖] [⟲] [☰]
  │           (⚙=настройки/правила/рестарт, 📖=правила, ⟲=рестарт, ☰=меню)
  ├─ Доска (центр, 90% площади)
  │    ├─ Кубики (центр доски, при броске)
  │    ├─ Уведомления (центр доски, поверх)
  │    └─ Tile-inspector (у выбранной клетки, авто-скрывается)
  ├─ Players-panel (лево, сворачивается)
  ├─ Journal (право, сворачивается)
  ├─ Action-panel (низ, только когда ход человека)
  ├─ Оверлей настроек/правил (поверх, по ⚙/📖)
  └─ Админка (F12, только хост, поверх всего)
```

## 4. Клетки и фишки

### 4.1. Клетка (tile_view.gd — переписать)

**Структура (зоны, не наложение):**

```
┌─────────────────────────┐  ← tile.svg (тёмная гравюра, рамка)
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │  ← цветная полоса группы (25% высоты)
│                         │     (modulate по цвету группы/типа)
│      ИМЯ КЛЕТКИ         │  ← 1–2 строки, шрифт масштабируется
│      (не обрезается)    │     (авто-уменьшение, не ellipsis)
│                         │
│  [иконка типа]   $220   │  ← иконка (SVG) + цена
│  [🏠🏠🏠]  [●влад]      │  ← домики (SVG house.svg) + маркер владельца
└─────────────────────────┘
```

Правила:
1. **Фон — `tile.svg`** (тёмная гравюра). Цвет группы — `modulate` на подложке
   (не перекрашивать весь тайл, а тонировать полосу + рамку).
2. **Имя:** авто-масштабирование шрифта (не ellipsis). Если не влезает в 2 строки —
   уменьшать кегль до 7px, потом сокращать по слову. Имя **никогда** не обрезается
   «…».
3. **Цвета:** тёмная тема. Полоса группы — насыщенный цвет (из `BoardTheme`),
   фон — тёмный. Текст — светлый (`#e8edf3`). Контраст ≥ 4.5:1.
4. **Владелец:** не 8×8 квадратик, а **цветная рамка вокруг клетки** (2px, цвет
   игрока) + маленькая точка-фишка игрока в углу. Видно издалека.
5. **Домики:** `house.svg` (зелёный домик) / `hotel.svg` (отель) — спрайты, не
   квадратики. 4 домика + отель.
6. **Иконки типов:** SVG из `assets/type_icons/` (tax, chance, community_chest,
   railroad, utility) — не юникод-глифы.
7. **Углы:** SVG из `assets/corner_icons/` (go_arrow, jail, free_parking,
   go_to_jail). GO — с зелёной подсветкой.

## 6. Тултипы / уведомления / таймер / кубики

### 6.1. Тултипы (требование №6 — У КАЖДОЙ кнопки)

- **Механизм:** `UiTheme.button()` уже принимает `tooltip` и применяет
  `_style_tooltip()`. **Обязательное правило:** любая кнопка/поле создаётся через
  `UiTheme.button(text, tooltip)` — без tooltip не создаётся (линтер-проверка).
- **Стиль:** тёмная подложка `#0d1117`, рамка accent `#4fb3d9`, шрифт 12px,
  авто-оборачивание, задержка 0.4s, позиция — под курсором (не закрывает кнопку).
- **Покрытие (чек-лист):**
  - Топбар: ⚙ (настройки/правила/рестарт), 📖 (правила), ⟲ (рестарт), ☰ (меню),
    👁 (наблюдатель).
  - Action-panel: все кнопки действий (roll/buy/pass/bid/pay/use_card/build/sell/
    mortgage/unmortgage/propose_trade/respond_trade).
  - Настройки: каждое поле (капитал, GO, тюрьма, дубли, …).
  - Players-panel: бейджи (тюрьма, банкрот, away).
  - Админка: каждая операция + каждый параметр.
  - Tile-inspector: кнопка закрыть.
  - Journal: фильтр.
- **Тултипы на EN/RU** — через i18n (см. §9).

### 6.2. Уведомления по центру (требование №11)

- **Механизм:** `ui/toast.gd` — новый виджет. Подписка на
  `engine.log.event_appended`. Маппинг через `EventMessages.describe` (уже есть).
- **Поведение:**
  - Появление: центр доски, над кубиками. Fade-in 0.2s, держим 2с, fade-out 0.3s.
  - Очередь: если событий больше — стопкой (макс. 3), не перекрываются.
  - Приоритет: `bankrupt`/`winner`/`jail` — крупнее + цвет (danger/gold/jail),
    остальные — стандартный.
  - Не блокирует ввод (mouse_filter = IGNORE).
- **Стиль:** тёмная плашка с рамкой-цветом события, иконка + текст. Пример:
  ```
  ┌─────────────────────────────┐
  │ 🏠 Host покупает «Lake Dr»  │  ← зелёная рамка (purchase)
  └─────────────────────────────┘
  ```

### 6.3. Таймер сверху (требование №12)

- **Где:** топбар, слева. Формат `⏱ 0:24` (мм:сс).
- **Логика:**
  - Берётся `seat.decision_waiting` (уже считается в seat_manager) и
    `settings.turn_timer` (или `auction_timer` в фазе AUCTION).
  - Остаток = `window - decision_waiting`.
  - Если `turn_timer == 0` (без лимита) — таймер **не показывается**.
  - Последние 5 секунд — цвет danger + пульсация.
  - При 0 — авто-пасс (уже в движке), таймер гаснет.
- **Дисплей:** моноширинный шрифт (чтобы цифры не «прыгали»), 16px.

### 6.4. Анимация кубиков (требование №13, как в BG3)

- **Механизм:** `visual/dice.gd` (новый). Два `TextureRect` с `assets/dice/die_<n>.svg`.
- **Сценарий броска (по событию `roll`):**
  1. Кубики появляются в центре доски (fade-in 0.15s).
  2. **Вращение:** 0.6s, случайные промежуточные грани (die_1..6 переключаются
     каждые 0.08s) + лёгкое подпрыгивание (scale 1.0→1.15→1.0) + вращение по Z
     (±30°).
  3. **Приземление:** 0.2s, финальные грани (d1, d2 из события), scale 1.0.
  4. **Показ суммы:** 1.5s, подпись «4+5=9» под кубиками (accent-цвет).
  5. Fade-out 0.3s (если нет следующего события).
- **Дубли:** если d1==d2 — подсветка (gold-рамка) + подпись «ДУБЛЬ!».
- **Отключение:** `settings.animations == false` → кубики показываются сразу
  (без вращения), сумма — 1с.
- **Не блокирует движок:** анимация — косметика, движок уже знает результат.

## 8. Админ-панель (требование №14)

### 8.1. Только у хоста

- **Флаг `is_host`** (из лаунчера: локальный запуск = true, webgl = false).
- На webgl: админка **не создаётся**, надпись «F12 — админ» **скрыта**, F12 не
  работает.
- Локально: F12 открывает админку. В топбаре — иконка [🛡] (только у хоста),
  тултип «Админ-консоль (F12)».

### 8.2. Понятность

- **Заголовок-подсказка:** «Выберите операцию → заполните параметры → Apply».
- **Тултипы:** у каждой операции (что делает) и каждого параметра (что значит).
- **Контекстные параметры:** показываются только нужные для выбранной операции
  (не все 6 SpinBox'ов всегда). Пример:
  ```
  Операция: [set_balance ▾]
  ┌─────────────────────────────────────┐
  │ Игрок: [Host ▾]   Сумма: [1500]     │  ← только pid + amount
  │ [ Apply ]  [ Сброс ]                │
  └─────────────────────────────────────┘
  ```
- **Live state:** таблица игроков (pid, имя, $, позиция, тюрьма, away, тайлы) —
  обновляется раз в секунду.
- **Event log:** последние 30, с фильтром.
- **Операции (с тултипами):**
  - `set_balance` — «Изменить баланс игрока»
  - `teleport` — «Переместить игрока на клетку»
  - `force_dice` — «Задать результат кубиков (d1, d2)»
  - `grant_property` — «Выдать клетку игроку»
  - `revoke_property` — «Забрать клетку у игрока»
  - `set_houses` — «Установить число домиков на клетке»
  - `set_mortgage` — «Заложить/выкупить клетку»
  - `set_go_jail` — «Отправить игрока в тюрьму»
  - `force_roll` — «Принудительный бросок текущего игрока»
  - `force_pass` — «Принудительный пасс текущего игрока»
  - `rollback_decision` — «Отменить последнее решение»
- **Стиль:** тёмная тема (как весь UI), не «голые» виджеты. Рамка danger-цветом
  (чтобы было понятно: это админка, не игра).

## 9. Локализация (требование №16)

### 9.1. Механизм

- **`ui/i18n.gd`** (новый): словарь `{key: {ru: "...", en: "..."}}` + `tr(key)`.
  ```gdscript
  const STRINGS := {
      "btn_roll":      {"ru": "БРОСИТЬ", "en": "ROLL"},
      "btn_buy":       {"ru": "КУПИТЬ", "en": "BUY"},
      "phase_purchase":{"ru": "ПОКУПКА", "en": "PURCHASE"},

  static func tr(key: String, lang: String = "ru") -> String:

  ```

  `tile_names_ru` (опционально, можно оставить EN-названия как «канон»).
