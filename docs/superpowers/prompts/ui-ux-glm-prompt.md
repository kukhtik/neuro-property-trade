# Промпт для старшего UI/UX-архитектора (glm 5.3 flash)

Запуск в отдельной сессии:
  hermes chat -m z-ai/glm-5.3-flash --provider openrouter
(или hermes, потом /model → z-ai/glm-5.3-flash)

Вставь текст ниже целиком:

---
Ты — старший UI/UX-архитектор. Проведи полный редизайн-анализ интерфейса настольной игры «Neuro Property Trade» (клон Monopoly, движок Godot 4.7.2, GDScript, тёмная тема, для стрима Neuro-sama). Твоя задача — НЕ писать код, а выдать концепцию полной переработки UX/UI, по которой потом будут переписывать интерфейс.

КОНТЕКСТ ПРОЕКТА
- Репозиторий: ~/projects/neuro-property-trade (локальный клон, читай файлы).
- Игра: движок-авторитет, игроки/ИИ подают интенты через seat_manager.push_intent. HUD читает for_spectator. UI-слой в game/ui/, визуал доски в game/visual/.
- Текущий UI: game/ui/theme.gd (палитра+фабрика виджетов), lobby.gd (стартовое меню), game_view.gd (игровой экран), top_bar.gd, players_panel.gd, action_panel.gd, tile_inspector.gd, modal_host.gd. Доска: game/visual/board_view.gd, token_panel.gd, tile_layout.gd, spectacle.gd, event_overlay.gd, sfx.gd.
- Ассеты (SVG, уже в game/assets/): 8 фишек (ship, top_hat, dog, cat, race_car, boot, iron, wheelbarrow), 4 угловые иконки (go_arrow, jail, free_parking, go_to_jail), 5 иконок типов (tax, chance, community_chest, railroad, utility), 6 кубиков (die_1..6), 2 дома (house, hotel), фон доски (board_center), кнопка (button), тайл (tile).
- Окно 1280×720, тёмная тема (фон #16191f), язык RU (нужна локализация EN).

ПРОБЛЕМЫ, КОТОРЫЕ НАДО РЕШИТЬ (от пользователя)
1. Стартовое меню (лобби) — зачем оно вообще отдельно от игры? Пользователь сомневается, что нужен отдельный экран настроек. Предложи, как объединить настройки с игрой (например, настройки прямо в игровом экране, или меню-оверлей поверх доски, или старт сразу в игру с дефолтами + настройки в панели).
2. Полная переработка UX/UI — текущий интерфейс «плохо выглядит», клетки накладываются, непонятно расположение.
3. Клетки: должны показывать цвет владельца, кол-во домиков, быть читаемыми (сейчас текст наезжает).
4. Фишки: у каждого игрока уникальная фишка + цвет (ассеты есть).
5. Справка клетки должна авто-скрываться через несколько секунд.
6. Тултипы: у КАЖДОЙ кнопки обязательное описание при наведении.
7. Правила — отдельной кнопкой, подробно, динамически из настроек.
8. Больше настроек игры (капитал, GO, тюрьма, дубли, застройка, залог, торги, агрессия ИИ).
9. Хост может быть наблюдателем (смотрит как ИИ играют).
10. Кнопка рестарта + меню настроек доступно из главного окна игры.
11. Уведомления посреди экрана о событиях.
12. Таймер сверху (в местах с ограничением по времени).
13. Анимация кубиков (как в Baldur's Gate 3).
14. Админ-панель только у хоста (на webgl даже надписи нет), и она должна быть понятной.
15. Обильное логирование для наблюдателя/тестов.
16. Полная локализация EN.
17. Адаптивность под разные размеры экрана.

ЧТО СДЕЛАТЬ
1. Прочитай текущий код UI (game/ui/*.gd, game/visual/*.gd) и ассеты (game/assets/), чтобы понять текущее состояние.
2. Дай критический разбор текущего UX/UI: что плохо, почему, что сломано.
3. Предложи ПОЛНУЮ концепцию переработки: структура экранов, навигация, компоновка игрового экрана, как объединить настройки с игрой, как выглядят клетки/фишки/панели, как работают тултипы/уведомления/таймер/кубики, как устроен режим наблюдателя, как выглядит админ-панель.
4. Дай конкретные рекомендации по компоновке (ASCII-схемы экранов), по цветам/стилю (тёмная тема, не-Hasbro), по иерархии информации.
5. Ответь на вопрос про стартовое меню: нужно ли оно отдельно, или настройки должны быть в игре.
6. Выдай итоговый документ-концепцию (markdown), структурированный по фазам/модулям, готовый к реализации.

ФОРМАТ ОТВЕТА
Верни полный markdown-документ «UI/UX-концепция» с разделами: (1) критический разбор текущего, (2) общая концепция и структура экранов, (3) компоновка игрового экрана (ASCII), (4) клетки и фишки, (5) настройки и стартовое меню, (6) тултипы/уведомления/таймер/кубики, (7) режим наблюдателя, (8) админ-панель, (9) локализация, (10) адаптивность, (11) приоритеты реализации. Пиши на русском. Будь конкретным и практичным — это пойдёт в реализацию.
