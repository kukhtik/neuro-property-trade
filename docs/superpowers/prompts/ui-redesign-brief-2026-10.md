# Neuro Property Trade — бриф на полный редизайн UI

> Назначение: дать дизайнеру (человеку или AI-модели) полное описание **текущего
> состояния интерфейса** и **технических требований** к новому макету, чтобы
> полностью переработать UI игры, не сломав движок.

---

## 1. Что за продукт

**Neuro Property Trade** — Monopoly-подобная игра про торговлю недвижимостью для
стрима на Neuro (AI-персонаж Vedal). Один движок, много «драйверов мест»
(seat drivers). Режимы (LOCAL / CHAT / REMOTE / sdk:neuro / sdk:evil / admin) —
это **конфигурация мест, а не отдельные игры**.

- **Движок**: Godot **4.7.2**, рендер `gl_compatibility` (OpenGL, работает на
  слабом железе / веб).
- **Запуск**: один лаунчер — `game/main.tscn` → `main.gd` → `GameView`.
- **Языки**: RU (по умолчанию) / EN, живое переключение без перестройки сцены.
- **Формат**: одноэкранный интерфейс (v2 «one-screen»). Никаких отдельных «лобби-сцен».
- **Съёмка для стрима**: поле OBS-совместимо, есть режим наблюдателя (нет LOCAL-места).
- **Контент**: 40 клеток (настраивается 16–64), 4 игрока (настраивается), касса 1500,
  полный набор правил Monopoly (аукционы, дома/отели, залог, торги, карты, тюрьма).

## 2. Текущий экранный состав (что уже есть)

Разрешение по умолчанию **1440×900**. Дерево строится кодом (`.gd`, без `.tscn`-сцен
для UI, кроме корня).

```
GameView (корень)
├── TopBar          — верхняя полоса HUD (высота 34)
├── HBoxContainer «center» (между TopBar и ActionPanel)
│   ├── PlayersPanel   — левая колонка игроков
│   ├── BoardScene     — поле (expand fill), содержит BoardView, камеру, спектакль, оверлей, SFX
│   └── PanelContainer → JournalPanel — правая колонка журнала событий
├── ActionPanel     — нижняя панель действий (высота 64)
├── ModalHost       — слой модальных окон (аукцион, торг, game over, т.д.)
├── TileInspector   — всплывающая карточка клетки (авто-скрытие)
└── ToastStack      — всплывающие уведомления
```

### 2.1 TopBar (HUD, верх)
- Титул **NEURO PROPERTY TRADE** + иконка-молния (слева).
- Справа: **`ХОД: <имя>`**, **`ФАЗА: <фаза>`** (напр. «Покупка»), иконка шестерёнки
  (настройки), иконка undo, метка **`F12 — админ`**.
- В cold-состоянии (до старта): **`до старта`** вместо ФАЗЫ.

### 2.2 PlayersPanel (левая колонка, «ИГРОКИ»)
- Список игроков: цветовой маркер, имя, касса (`$1500`), позиция
  (`@ Palm Row · 0 тайл.`), счётчик клеток.
- **Активный игрок**: подсветка рамкой + маркер `▶ ход`.
- Клик по строке (режим наблюдателя) — переключение слежения камеры.
- В cold-состоянии: **«Партия ещё не начата»**.

### 2.3 BoardScene (центр, поле)
- **Кольцо-периметр** из 40 клеток (геометрия Monopoly, 11 на сторону).
- Каждая клетка (`tile_view.gd`): цветовая группа (полоса), имя, цена, иконки,
  дома/отели, маркер владельца, рамка выделения.
- **Токены игроков** (`token_panel.gd`): цветные фигуры с инициалами, разлёт при
  совпадении клетки, анимация шага.
- **Кубики** в центре поля (`dice_stage.gd`).
- **Мини-лог** в центре поля (debug-стиль).
- **Камера-спектакль**: `clip_contents`-фрустум панорамирует поле к «событию»
  (бросок/ход/покупка); учитывает `settings.animations`.
- **Центральная зона пустая** (нет логотипа/графики).

### 2.4 JournalPanel (правая колонка, «ХОД СОБЫТИЙ»)
- Фильтры сверху: `игрок` (dropdown), `тип` (dropdown), тумблер `$`, счётчик `15/15`,
  иконка колонок.
- Пронумерованный скроллируемый список событий; часть строк подсвечена.
- В режиме наблюдателя ширина журнала **380px** (несёт 100+ строк).

### 2.5 ActionPanel (низ, 64px)
- Кнопки хода: бросок, покупка/пас, ставка в аукционе, билд/продажа, торги и т.д.
- Контекстно зависит от фазы и легальных действий.
- Плавающие кнопки (`dice_stage`, `timer_ring` — кольцо таймера хода).

### 2.6 Модальные окна (ModalHost)
- **Аукцион** (`Аукцион: «тайл N»`): ставка/пас.
- **Торг** (propose/respond): обмен клетка+деньги.
- **Game over**: победитель.
- Прочие подтверждения.

### 2.7 SettingsOverlay (один оверлей, заменяет старое лобби)
Открывается до старта и из шестерёнки. Заголовок **НАСТРОЙКИ МАТЧА**.
- **Пресеты**: `Классика`, `Быстрая партия`, `Хардкор`.
- **5 табов**:
  1. **Игроки** — список мест (драйвер: ЛОКАЛ/ИИ/CHAT/SDK), имя, тумблер цвета,
     выбор жетона (ship/top_hat/dog/cat/…), кнопка `×` удалить; `+ добавить игрока`.
     Внизу: `Роль хоста: играю (LOCAL)`, `Нач. порядок: случайный`.
  2. **Правила** — `starting_cash`, `go_bonus`, `jail_rule`, `jail_fine`,
     `free_parking`, `doubles`, `triple_doubles`, `auctions`, `housing`,
     `even_build`, `monopoly_x2`, `mortgage`, `loan_pct`, `repay_pct`, `trades`,
     `ai_aggression`.
  3. **Темп** — `turn_timer`, `auction_timer`, `timeout_action`.
  4. **Интерфейс** — `animations`, `event_overlay`, `spectacle`, `language`, `sound`.
  5. **Данные** — `rng_seed`, `tile_count` (16–64, кратко 4), сброс.
- Кнопки: **▶ СТАРТ ПАРТИЮ** (до старта) / **ПРИМЕНИТЬ** (перезапуск), **ПРАВИЛА**.
- Кнопки в заголовке: `сброс`, `× ESC`.

## 3. Подтверждённые дефекты текущего макета (исправить в новой версии)

Снято рендером Godot 4.7.2, `vision_shots.tscn`, 1440×900:

1. **Стопка одинаковых окон «Аукцион: «тайл 6»»** — 5 штук каскадом поверх поля.
   Модалка дублируется / не закрывается. Поле, кубики и лог перекрыты.
2. **Дубль панели «ХОД СОБЫТИЙ»** — вторая пустая панель в правом нижнем углу.
3. **Обрезанные подписи клеток** — `Lak...`, `Fort...`, `F...` — читаемость поля сломана.
4. **Мини-лог в центре поля перекрыт** аукционными окнами.
5. **Debug-теги в логе**: `[auction_bid]`, `[auction_pass]`, `[cash]`, `[pass_on_purchase]` —
   не юзер-фейсные, идут вперемешку с русским текстом.
6. **Пустая центральная зона поля** — нет логотипа/декора, доска «голая».
7. **Смешение языков**: английские `[теги]` + русские строки + `p0/p1/p2` вместо имён.
8. **Таб «Игроки»** в настройках — большая пустая зона.

## 4. Технические требования к новому макету

### 4.1 Обязательные инварианты (ломать нельзя)
- **Движок авторитетен.** UI — только потребитель: читает через
  `Projection.for_spectator(engine)` и слушает `engine.log.event_appended`.
  UI **никогда** не мутирует состояние движка напрямую.
- **Fail-closed intent API.** Любое действие — через
  `manager.push_intent(pid, action, params)`; движок сам валидирует.
- **Spectator-safe.** Всё, что рисуется/логируется из проекции наблюдателя, не должно
  содержать приватных данных (скрытые ставки аукциона, карты «выход из тюрьмы»).
- **Один лаунчер** — `game/main.tscn`. Dev-инструменты (пробы/соак/скриншоты) — отдельные
  команды, не в игровом меню.
- **i18n.** Все строки через `I18n.t("key")`; словари в `game/i18n/`. Никакого
  захардкоженного текста. Переключение RU/EN — живое, без перестройки сцены.
- **Локализованные OptionButton** читать по **индексу/ID**, а не по тексту (иначе
  раскладка ломает парсинг значений движка).
- **Тема — единый источник.** Сейчас два: `ui/theme.gd` и `visual/theme.gd`.
  Новый макет должен свести к одному (палитра, шрифты, размеры, радиусы, отступы).

### 4.2 Адаптивность (текущая таблица брейкпоинтов)
- Ширина ≥1600: панели left 260 / right 320.
- Ширина ≥1280: left 240 / right 300.
- Иначе: left 150 / right 180 (минимум).
- Режим наблюдателя: журнал 380.
- Есть компакт-режим (проверено 900×600).
- **Требование**: новый макет обязан быть протестирован на ≥4 разрешениях и в
  компактном режиме; панели не должны «схлопываться» в пустые полосы.

### 4.3 Технологические границы
- **Без растрового пайплайна**: поле строится кодом из `board.json` (оригинальная
  тема, НЕ Hasbro — см. `docs/licensing.md`). SVG-ассеты допустимы (скины в
  `game/assets/skins/<id>/skin.json`), растровый тяжёлый арт — пока нет.
- **SkinManager** (`visual/skin_manager.gd`) — точка подмены темы/скина.
- Параметрическое поле: `settings.tile_count` (16–64) должно работать в новом макете.
- **SFX**: процедурные то́ны (`visual/sfx.gd`), без файлов. Можно звук — но не обязателен.
- **Экспорт**: WebGL (`--export-debug "Web"`) должен продолжать собираться.

### 4.4 Производительность / платформа
- `gl_compatibility` (OpenGL 4.6, llvmpipe-совместимо для тестов).
- Целевое железо — стрим-ПК + потенциально слабый ноут/веб.
- UI должен УГАДЫВАТЬСЯ без пересоздания сцены на смене языка (live relabel).

### 4.5 Ограничения на переработку
- **Движок трогать нельзя.** Новый макет касается только слоя `game/ui/*`,
  `game/visual/*`, `game/i18n/*`.
- **Контракт с движком** (не менять без согласования):
  - вход: `Projection.for_spectator(engine)`, `engine.log.event_appended`, `legal_actions`,
  - выход: `manager.push_intent(pid, action, params)`.
- Есть **UI-contract тесты** (`game/tests/ui_contract_runner`) — новый макет должен их
  проходить (или они обновляются в том же рефакторе, с фиксацией полного состояния).

## 5. Что должен дать новый макет (deliverable)

1. **Все экраны** в одном визуальном языке: cold/lobby, live-board, observer,
   auction, trade, game-over, settings (все 5 табов), compact.
2. **Исправление 8 дефектов** из §3.
3. **Один источник темы** (§4.1), палитра + типографика + токены отступов.
4. **RU + EN**, живые переключатели, без захардкоженного текста.
5. **Адаптивность** на 4+ разрешениях и в compact (§4.2).
6. **Спека состояний**: для каждого экрана — DOM-подобное дерево, размеры,
   состояния (hover/active/disabled/empty/overflow).
7. **Статичный прототип** (например, HTML), который можно приложить к движку 1:1.

---

## 6. Формат ответа от дизайнера

- ASCII/визуальные концепты **до** реализации (утверждение).
- Для каждого экрана: назначение, зоны, иерархия, поведение, состояния.
- Явно: что осталось от текущего, что добавлено, что убрано (и почему).
- Токены темы (цвет/шрифт/размер/отступ/радиус) в виде таблицы.
- Список рисков совместимости с §4.
