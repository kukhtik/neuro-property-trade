## 1. Что сломано — измерено, не оценено

Замеры на живом кадре `build/ab/turn-human_neuro.png` (1600×1200, снят самим приложением
`sg07_capture`, скин neuro) и на дампе дерева (`get_global_rect` каждого Control).

| Что | Замер | Норма |
|---|---|---|
| Пустых ячеек кадра (сетка 40×30) | **51.7 %** (621 из 1200) | ≤ 25 % |
| Пикселей, занятых осмысленным содержанием | **4.2 %** (80 558 из 1 920 000) | ≥ 40 % |
| Центр доски (857×800) | **пусто 84.7 %**; занято по высоте 94 px из 800 | ≥ 70 % |
| Что в центре | `_banner` 35 px + `_tray` 59 px | — |
| `_card` (карточка события) | 428×92, **скрыта** | видна на ходу |
| `_sum` (сумма броска) | **3 px шириной**, скрыта | читается |
| Рейлы (48 px × 2) | 53 760 px каждый, в свёрнутом виде — пустая полоса | несут смысл или отсутствуют |
| Карточки игроков | **242×245 px при 2 строках текста** | плотность по R-3 |
| Текст с телефона 390 px | **2.4–3.2 px** | ≥ 12 px |

Два числа про пустоту измеряют РАЗНОЕ и оба верны: «51.7 % ячеек пусты» — про топологию
(какие участки экрана вообще ничего не рисуют), «4.2 % пикселей — смысл» — про плотность
(сколько площади занято информацией, а не рамками и фоном клеток). Владелец говорит «пусто
везде» — и это подтверждается обоими: половина экрана не рисует ничего, а осмысленное
содержание занимает одну двадцать пятую его часть.

**Что это значит.** Доска — рамка из клеток, внутри неё дыра размером с треть экрана. Вся
информация о ходе (кубики, событие, деньги игроков, журнал) лежит в боковых панелях 48 px,
которые в свёрнутом виде не показывают ничего, либо скрыта флагом. Приложение тратит 96 %
пикселей на пустоту и декор при **девяти обязательных блоках информации**.

**Причина — не вёрстка.** `board_scene._place_centre` (строки 192–218) рассчитывает центр как
«поднос с кубиками + строка события»: `_tray` 59 px, `_banner` 30 px. Места в центре — на 9×9
клеток, то есть треть кадра отдана двум элементам высотой 94 px суммарно.

## 2. Принципы, которые продукт нарушает сейчас

Из `design/DESIGN.md` §1 («Broadcast Table», 5 принципов). Проверено против живого кадра:

| Принцип | Формулировка | Состояние |
|---|---|---|
| **P-1** | «Доска — герой. Кольцо целиком, всегда. Панели обслуживают доску, не спорят с ней.» | **НАРУШЕН**: кольцо есть, но 84.7 % его нутра — дыра; информация в панелях, которые прячутся |
| **P-3/P-4** | «Две роли текста — значение и абзац. Ни один элемент не полагается на третью.» | **НАРУШЕН**: `jrn-text` (12 px, переносится) и `top-round` (13 px, не переносится) — одна роль на разные вещи |
| **P-5** | «Уведомление не поверх игры» | выполнен |
| **P-7** | «Один герой-экшен в консоли, остальное — вторичные кнопки с тултипами» | выполнен |
| **P-14** | «Токен до последнего пикселя» | выполнен |

**Вывод:** нарушены ровно те два принципа, которые отвечают за «понятно с одного взгляда».
Отсюда и жалоба владельца.

## 3. Требования (обязательные, проверяемые)

Обозначения: **MUST** — без этого работа не принята; **MUST NOT** — запрет.

### 3.1 Заполненность

- **R-1 (MUST).** Не более **25 %** пустых ячеек кадра. Порог проверяемый: кадр делится на
  сетку 40×30, пустой считается ячейка, где < 2 % не-фоновых пикселей. **Сегодня — 51.7 %.**
- **R-2 (MUST).** Внутри кольца доски занято не менее **70 %** площади. Сегодня — 15.3 %.
- **R-3 (MUST).** Ни одной панели, чьё содержимое — меньше 2 строк текста, при площади
  больше 40 000 px. Сегодня — все четыре карточки игроков (242×245 при двух строках).

### 3.2 Понятность

- **R-4 (MUST).** На ходу одновременно видны и различимы: чей ход, фаза, кубики с суммой,
  деньги всех игроков, последнее событие. Сегодня: видны «чей ход» и «фаза»; кубики — пустой
  поднос; деньги всех игроков — только в свёрнутых рейлах; событие — строкой 12 px.
- **R-5 (MUST).** Ни один элемент, несущий смысл хода, не скрыт флагом `visible=false`
  в состоянии «идёт матч, ход человека». Сегодня `_card` и `_sum` скрыты.
- **R-6 (MUST NOT).** Ни одного «особого режима». Один и тот же интерфейс для игрока,
  наблюдателя и стрима; различаться может только доступность кнопок.

### 3.3 Читаемость

- **R-7 (MUST).** Каждый элемент из списка «glance» (см. `stream_read_gate.gd`, `GLANCE_SET`)
  имеет кегль **≥ 59 px** в кадре 1920×1080, то есть **≥ 12 px** после сжатия до телефона
  390 px. Сегодня: 10–13 px → 2.4–3.2 px. **Это главное требование, и оно определяет вёрстку.**
- **R-8 (MUST).** Роль текста определена явно: значение — не переносится ни при каком
  размере; абзац — переносится. Один элемент не может быть обеими (нарушение P-3).

### 3.4 Значки и слова

- **R-9 (MUST).** Ни один орган управления не подписан одним символом. Кнопка читается словом.
  Сегодня выполнено (коммит `aa0068b`); запрет сохраняется для новых элементов.
- **R-10 (MUST).** Ни один видимый символ не лишён глифа в шрифте. Гейт `GLYPH` — красный при
  возврате. Разрешены только `— • … →`.

### 3.5 Ничего не теряется

- **R-11 (MUST).** Каждое из 9 обязательных сведений (см. §1 перечень) доступно без действий,
  требующих догадки: либо видно сразу, либо за кнопкой со словом на ней.
- **R-12 (MUST).** Ни одно требование не выполняется удалением функции. Если элемент убран —
  в спецификации указано, где его смотреть.

## 4. Схема переработки

### 4.1 Центр доски становится панно хода

Центр (9×9 клеток = 857×800 px при кадре 1600×1200) перестаёт быть фоном. Внутри него — четыре
зоны, в порядке чтения сверху вниз:

| Зона | Высота | Что несёт |
|---|---|---|
| **Бросок** | 170 px | кубики + сумма цифрой (кегль по R-7) |
| **Событие** | 210 px | карточка: покупка, аренда, шанс/казна, отказ |
| **Игроки** | 230 px | 4 строки: цвет, имя, деньги, число владений |
| **Журнал** | 150 px | 3 последних строки |

Итого 760 px из 800 → **95 % центра занято** (R-2 выполнен).

Требования, вытекающие отсюда:
- **R-13 (MUST).** Панно строится ОДНИМ модулем с одной раскладкой; ни один элемент внутри не
  позиционируется абсолютными координатами от размера экрана.
- **R-14 (MUST).** Панно — потребитель проекции (`sdk/projection.gd`), как и остальная оболочка.
  Оно не вычисляет игровое состояние само.

### 4.2 Панели перестают быть обязательными

- **R-15 (MUST).** Рейлы 48 px удаляются, если их содержимое переехало в панно (R-5, R-2).
  Оставшиеся панели не сворачиваются в пустую полосу: свёрнутая панель показывает слово
  (R-9), а не пустоту.
- **R-16 (MUST).** Шапка и консоль сохраняют читаемость при 880×600 (компакт) — это проверяет
  `SG-01`; панно при этом профиле может скрывать зону «журнал», но не «бросок» и не «событие».

### 4.3 Читаемость как главный ограничитель

R-7 имеет приоритет над размером доски, но **доска остаётся героем** (P-1):

- **R-17 (MUST).** Доска не уменьшается ниже **77 px на клетку** (сегодня 95 px). Это
  ограничивает долю, которую может занять шапка/панно по высоте.
- **R-18 (MUST).** Если R-7 и R-17 конфликтуют при данном размере окна, растёт **высота кадра**
  (`LayoutProfile.screen`), а не сжимается доска. Обоснование: доска квадратная, её размер
  упирается в высоту окна, поэтому высота — ручка читаемости, а не размер шрифта.

## 5. Проверка (обязательная до «готово»)

Каждое требование — с процедурой и, где возможно, с негативной проверкой.

| # | Проверка | Как | Красный за |
|---|---|---|---|
| R-1 | доля пустоты | замер кадра сеткой 40×30 | > 25 % |
| R-2 | заполненность центра | замер области кольца | < 70 % |
| R-3 | панели-пустышки | дамп дерева: площадь / строки | площадь > 40k при < 2 строках |
| R-4/R-5 | видно на ходу | дамп `get_global_rect` + `visible` для 5 сведений | любое скрыто или отсутствует |
| R-6 | нет режимов | счёт мест в UI, где ветка зависит от роли | ветка, меняющая раскладку |
| R-7 | читаемость | гейт `STREAM-READ` (существует) | любой glance-элемент < 59 px |
| R-9 | слова | гейт `GLYPH` (существует) | символ вне `— • … →` |
| R-10 | глифы | гейт `GLYPH` | `has_char` = false |
| R-13 | одна раскладка | ревью: нет литералов координат в панно | литерал |
| R-17 | клетка ≥ 77 px | замер клетки на 4 профилях | < 77 px |

**Новые гейты, которые нужно написать** (в карантин, затем в required):
1. `FILL` — R-1, R-2 (доля пустоты кадра и центра). Мерит пиксели, как `SG-03`.
2. `PANEL-NOT-EMPTY` — R-3 (панель не может быть пустой). Мерит дерево, как `SG-11`.

Оба обязаны **падать при возврате дефекта** (негативная проверка) — иначе это не гейт.

## 7. Порядок работ

Каждый шаг заканчивается зелёным оракулом и затронутыми гейтами.

1. **Гейт `FILL`** — сначала измерение, потом правка. Иначе переработка недоказуема.
2. **Панно центра** (`board_scene._place_centre` → модуль панно), R-13/R-14.
3. **Переезд рейлов** в панно, R-15; удаление пустых панелей.
4. **Читаемость** R-7: кегли из `LayoutProfile`, `screen` как ручка R-18.
5. **Гейты** `FILL` + `PANEL-NOT-EMPTY` из карантина в required после 2 зелёных прогонов.
6. **Доки**: `program.md`, `gates.md`, `design/DESIGN.md` §1 — записать, что P-1/P-3 снова
   выполнены.

**Критерий готовности:** все требования §3 выполнены, §5 зелёные, негативные проверки
проведены, оракул `ran N tests, 0 failed`, `docs/program.md` обновлён в том же коммите.

## 8. Что НЕ входит

- Смена дизайн-системы. «Broadcast Table» остаётся; чинятся два нарушенных принципа.
- Новые палитры и скины. Токены не трогаются.
- Оверлей для стрима. **Запрещён владельцем**: «интерфейс должен быть всегда таким, чтобы
  был понятен. никаких особых режимов».
- Уменьшение доски ниже 77 px на клетку (R-17).
