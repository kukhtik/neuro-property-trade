# NPT UI — бриф дизайнеру

Приложение: **Neuro Property Trade** — настольная игра о торговле недвижимостью, Godot 4.7.2.
Экран один, раскладка адаптивная. Дата брифа: 2026-10-12.

Разбор причин, на который опирается этот документ: `docs/specs/ui-defect-report.md`.

---

## 1. Источник истины — макет, а не этот текст

Макет — **не картинка, а спецификация**: он несёт свои значения в машиночитаемом виде, и
проект умеет их сверять.

| Ось | Что объявляет макет | Как проверяется |
|---|---|---|
| Палитра | `:root[data-theme="neuro"]` | `compare_mockup.py` — 11 токенов, по значению |
| Колонки | `--L: 272px`, `--R: 330px` | по **пропорции**, не по пикселям |
| Структура | `top mid pl stage jr act` | по наличию регионов в кадре |

```sh
python tools/ci/compare_mockup.py neuro     # сверка значений — это гейт
python tools/ci/side_by_side.py  neuro      # макет и приложение рядом: посмотреть глазами
```

Пропорция колонок: макет `272/330 = 1.21`, приложение должно держать то же **отношение**.
Приложение занимает экран целиком; макет свёрстан с полями по краям — это не расхождение.

**Порога «похоже» не существует** и выдумывать его не нужно: разные рендереры, шрифты,
масштабы. `side_by_side.py` выдаёт картинку и на этом останавливается.

## 2. Из чего состоит экран

Шесть регионов макета и что в них живёт:

| Регион | Содержимое | Ширина |
|---|---|---|
| `top` | шапка: роль, раунд, язык, таймер хода | во всю ширину |
| `pl` | панель игроков: строки мест, блок STATISTICS, полоса владения | левая рейка |
| `stage` | доска 40 клеток, токены, кубики, центральный блок | растягивается |
| `jr` | журнал: фильтры, лента событий, экспорт | **правая рейка** |
| `act` | панель действий: кнопки текущего решения | снизу |
| `mid` | инспектор клетки: цена, рента, владелец | поверх правой рейки |

Палитра — токены скина `game/assets/skins/neuro/skin.json`, 11 сверяемых:
`bg`, `surface.1..3`, `line`, `text`, `muted`, `accent`, `on_accent`, `accent2`, `money`.
Сверх них есть смысловые: `danger`, `warn`, `player`, `group`, `ev.money`, `ev.build`,
`ev.card`, `ev.danger`, `ev.text`, `ev.accent`, `board.bg2..3`.

---

## 3. Что сломано визуально сейчас

1. **Метки в горизонтальных строках растягиваются.** Значения денег, бейджи хоткеев,
   счётчики тянут свободную ширину и выталкивают соседей. Строка перестаёт читаться
   колонками. Сейчас это 17 меток в четырёх панелях.
2. **Однострочные подписи переносятся там, где перенос не нужен.** Короткое `Игрок 1`
   в узком месте становится двумя строками; высота строки меняется, список дёргается.
3. **Абзацы в рейках наоборот не оформлены как абзацы.** Перенос им нужен — но он должен
   быть свойством панели, а не побочным эффектом фабрики меток.
4. **Пропорция колонок поехала** относительно объявленной `1.21`.

Всё четыре — следствие одной правки (`game/ui/theme.gd`, коммит `3d6928c`). Подробности
и замеры — в отчёте о дефектах.

## 4. Правила, которые дизайн должен явно выразить

Это то, чего не хватало и что привело к поломке. Просьба зафиксировать их в макете
как роли текста, а не оставлять на усмотрение кода.

### 4.1. Две роли текста — и это разные компоненты

| Роль | Перенос | Ширина | Примеры |
|---|---|---|---|
| **Значение** | никогда | по содержимому, не растягивается | `$1500`, `3 дома`, `F12`, `×2` |
| **Абзац** | да, по словам | занимает ширину родителя | правила, описание клетки, подсказка |

Смешивать их нельзя: значение, которое переносится, ломает строку; абзац, который не
переносится, уезжает за край.

### 4.2. Правило оси

Растяжение по ширине — свойство **контейнера**, а не текста. В строке растягивается
ровно один элемент (обычно «пружина» или основная подпись); все остальные — по
содержимому. Просьба помечать в макете, что тянется, а что нет.

### 4.3. Минимальные ширины реек

Левая и правая рейки имеют объявленные ширины. Их отношение `1.21` — **гейт**, а не
пожелание: `compare_mockup.py` его проверяет. Если дизайн хочет другое отношение —
это меняется в макете, и уже оттуда попадает в код.

### 4.4. Токены, а не цвета

Ни один цвет в спецификации не задаётся значением. Только имя токена. Значения живут
в `skin.json` и сверяются байт-в-байт.

---

## 5. Что нужно от дизайнера

1. **Обновлённый макет** с явными ролями текста (§4.1) и пометками оси (§4.2).
2. **Список расхождений** между текущим экраном и макетом — на основе
   `side_by_side.py`, глазами. Если расхождение вызвано дефектом из §3, помечать его.
3. **Решение по трём панелям**, где текст должен переноситься: журнал, инспектор клетки,
   подсказки действий. Что переносится, что обрезается многоточием, при какой ширине.
4. **Поведение при узком окне.** Сейчас раскладка адаптивная; нужен явно описанный
   порядок, что ужимается первым.

---

## 6. Что дизайнеру НЕ нужно решать

- Цены, ренты, правила — это данные (`game/data/board.json`), не дизайн.
- Число клеток — 40; параметризация заложена, файлов других размеров пока нет.
- Палитра — задана токенами, менять её можно, но через `skin.json`.

---

## 7. Известные ловушки скинов

Замерено по файлам скинов, дизайну знать полезно:

| Скин | Цвета | Размеры |
|---|---|---|
| `neuro` (по умолчанию) | полные | есть |
| `default` | полные | есть |
| `evil` | полные | **нет** |
| `classic` | **пустые** | **нет** |

Скин `classic` объявляет пустую палитру: если его выбрать, интерфейс рисуется
фолбэками. Либо наполнить, либо убрать из списка. Для `evil` нужны размеры.
