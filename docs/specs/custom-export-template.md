# P3.6 — свой шаблон экспорта: сколько весит движок и что можно срезать

Статус: **оценка (design-only)**. Правок продукта, реестра и CI в этой карточке нет.
Дата замера: 2026-10-23. Артефакт получен измерением на этой машине + официальные
числа Godot 4.4 docs; всё, что я не смог измерить, помечено явно.

## 1. Текущий вес движка (число)

### 1.1. Что записано в программе и подтвердилось ли это

| Источник | Число | Подтверждено измерением? |
|---|---|---|
| `docs/program.md:561` | `index.wasm` = **39 514 754 B** | **НЕТ** — см. 1.2 |
| `docs/program.md:713` (приёмка P3.6) | «текущий `index.wasm` = 39 514 754 B» | **НЕТ** |
| `docs/acceptance/definition-of-done.md:99` | «движок `index.wasm` (39 514 754 B) в 58 раз больше пака» | **НЕТ** |
| `README.md:142` | «the engine itself (`index.wasm`, 39.5 MB)» | **НЕТ** |

### 1.2. Почему число из программы не подтвердилось

Каталога `build/` нет ни в рабочем дереве карточки, ни в основном репозитории:

```
$ ls -d build                      -> 'NO build in worktree'
$ ls -d <main-repo>/build           -> 'NO build in main repo'
$ du -sh build                      -> (пусто, каталога нет)
$ find <main-repo>/build -name '*.wasm' -> (пусто)
```

Причина видна в `.gitignore` (строки `build/`, `build/web/`): каталог сборки не версионируется,
а в этой рабочей копии он не пересобирался. **`index.wasm` в поставке на диске отсутствует —
измерить нечем.** Это прямое «не хватает данных»: 39 514 754 B остаётся утверждением доков.

### 1.3. Чем заменил: закреплённый шаблон движка (измерено)

`.tools/godot-version` = `4.7.2`; `tools/ci/fetch_templates.sh:14` качает шаблоны именно этой
версии, и они установлены на машине:

```
C:\Users\Nitro\AppData\Roaming\Godot\export_templates\4.7.2.stable\
  web_release.zip   10 290 815 B
  (внутри) godot.wasm   38 820 072 B   magic 0061736d, version 1
```

`38 820 072 B` — это **фактический вес движка, который уходит в поставку с закреплённым
шаблоном** (экспорт `Web` переименовывает `godot.wasm` → `index.wasm`,
`game/export_presets.cfg:17` `export_path="build/web/index.html"`).

**Расхождение с доком: 39 514 754 − 38 820 072 = 694 682 B (+1,79 %).**
То есть число из программы **на 1,79 % больше** движка из закреплённого набора шаблонов:
оно получено сборкой, которую текущий пин шаблонов не воспроизводит (другая ревизия
движка либо иной набор флагов). Для всех оценок ниже базой беру **измеренные 38 820 072 B**,
а не число из доков.

### 1.4. Из чего состоят эти байты (разбор секций wasm)

| Секция | Байт | Доля |
|---|---|---|
| `code` | **33 763 223** | 87,0 % |
| `data` | **4 747 939** | 12,2 % |
| `elem` | 226 167 | 0,58 % |
| `func` | 74 309 | 0,19 % |
| `type` | 5 701 | 0,01 % |
| `import` | 2 453 | 0,01 % |
| `export` | 169 | — |
| `global` / `table` / `start` / `datacount` / `tag` | 49 / 9 / 3 / 2 / 3 | — |
| **custom-секции (имена, debug)** | **0** | 0 % |

Вывод: **бинарник уже stripped** — срезать «мусор» из самого файла нечего (совпадает с
[Godot docs, «Stripping binaries: Performed in official builds: Yes»]). Экономия возможна
только за счёт **удаления кода и данных неиспользуемых подсистем при сборке**.

### 1.5. Вес на проводе (то, что реально качает игрок)

```
$ gzip -9 godot.wasm -> 10 111 470 B   (26,0 % от raw)
```

Сырые 38,8 МБ по HTTP не едут: с gzip это **≈ 9,65 МиБ**. Любую экономию ниже надо читать
в двух числах — raw и gzip; доля gzip ≈ 26 % от raw (для срезанного бинарника эта доля
может быть иной — см. §4.3).

### 1.6. Контекст (числа для карточки)

| Метрика | Значение | Команда |
|---|---|---|
| файлов под git (в рабочем дереве карточки) | **863** | `git ls-files \| wc -l` |
| `du -sh build` | **нет каталога** | `du -sh build` |
| вес пака (измерено ранее, `docs/program.md:552`) | 676 612 B | — |
| `index.wasm` : пак | 38 820 072 / 676 612 ≈ **57,4×** | расчёт по двум числам выше |

### 1.7. ICU внутри движка (важно для §2 и §4)

В data-разделе присутствуют данные ICU:

```
строки: "icudt78l", "ICU break iteration data (\"icudt_godot.dat\")",
        "res://icudt_godot.dat", локали ("Volapük", "Kumyk", "Kalmyk", ...)
заголовок UDataInfo (0xDA27) на смещении 4 037 527 внутри data-раздела
  -> от него до конца раздела: 4 747 939 − 4 037 527 = 710 412 B
```

Границы измерены (≥ 710 412 B, верхняя — весь data-раздел 4 747 939 B), но **точное вхождение
ICU без сборки не отделяется: не хватает данных**. Для сравнения: тот же набор шаблонов
кладет для нативных сборок `icudt_godot.dat` = 4 797 472 B.

## 2. Что можно отключить в своём шаблоне экспорта

Базовый факт: официальные шаблоны собраны «со всем» — по [Godot docs 4.4, Optimizing a build
for size](https://docs.godotengine.org/en/4.4/contributing/development/compiling/optimizing_for_size.html)
у всех рычагов ниже стоит «Performed in official builds: **No**». Список модулей движка —
57 каталогов в `modules/` тега `4.7.2-stable` (замер: GitHub trees API, `modules/*`).

### 2.1. Рычаги с официальной оценкой экономии

| Рычаг | Флаг | Оценка в доках | Уже применён? |
|---|---|---|---|
| Отключить 3D | `disable_3d=yes` | **«binary size can be reduced by about 15 %»** (Moderate) | нет |
| Отключить продвинутый текстовый сервер | `module_text_server_adv_enabled=no module_text_server_fb_enabled=yes` | **High** | нет |
| Отключить продвинутые GUI-виджеты | `disable_advanced_gui=yes` | Moderate | нет |
| Отключить ненужные модули | `module_<name>_enabled=no` | Very low…Moderate | нет |
| Stripping / LTO / `optimize=size` | — | Very high / High / High | **да** (custom-секций 0, web по умолчанию `optimize=size`) |

### 2.2. Набор, который предлагается резать, и доказательство неиспользования

Доказательство — `git grep` по продукту `game/` (пустой вывод = API не используется):

**Этап 1 — 3D (`disable_3d=yes`)**
- `git grep -c "Node3D\|Camera3D\|MeshInstance3D\|CharacterBody3D\|RigidBody3D\|PhysicsServer3D\|Viewport3D\|GridMap\|CSGShape\|GLTFDocument\|NavigationServer" -- game` → **пусто**.
- Оговорка из доков: `disable_3d` отключает и навигацию вообще (2D тоже). Навигации в продукте нет (тот же пустой grep).
- Игра 2D-ная: `game/project.godot` `renderer/rendering_method="gl_compatibility"`, корень `game/main.tscn`, ассеты — только `.wav` и картинки.

**Этап 2 — текстовый сервер (`text_server_adv` → `text_server_fb`)**
- В движке это самый крупный единичный кусок данных: ICU (см. §1.7) + HarfBuzz/Graphite.
- Доки прямо разрешают замену: «If you only intend on supporting Latin, Greek and Cyrillic-based
  languages in your project, the fallback text server should suffice… a good fit for mobile/web».
- Состав i18n: `game/i18n/{i18n.gd,data_ui.gd,data_event.gd,data_admin.gd,data_settings.gd,data_action.gd}`
  (языки — в `i18n.gd`; отдельных файлов шрифтов в `game/assets/**` нет: `git ls-files game/assets | grep -iE '\.(ttf|otf|woff)'` → пусто).

**Этап 3 — ненужные модули (по списку 57)**

| Группа | Модули (`module_*_enabled=no`) | Доказательство |
|---|---|---|
| XR | `openxr`, `webxr`, `mobile_vr` | grep по `OpenXR`/`XR` в `game/` пуст |
| Видео | `theora` | `VideoStream` в `game/` — пусто |
| Кодеки звука | `ogg`, `vorbis`, `mp3` | `game/assets/audio/` = 12 файлов `.wav` (+`.import`), других форматов нет |
| Импорт моделей | `gltf`, `fbx` | grep пуст; в `game/assets` нет `.glb/.gltf/.fbx` |
| 3D-физика/навигация | `jolt_physics`, `godot_physics_3d`, `navigation_3d`, `navigation_2d` | grep пуст |
| Сеть сверх WebSocket | `enet`, `upnp`, `webrtc`, `jsonrpc` | `git grep ENetMultiplayerPeer\|MultiplayerAPI\|SceneMultiplayer -- game` → пусто; транспорт — `WebSocket` (`game/server/game_server.gd:11`, `game/addons/neuro-sdk/websocket/websocket.gd:6`) |
| Текстуры/импорт-экстры | `astcenc`, `etcpak`, `ktx`, `cvtt`, `dds`, `tinyexr`, `hdr`, `tga`, `bmp`, `svg`, `webp` | ассеты — `.png`/`.wav`; SVG/EXR/DDS/KTX в дереве нет |
| Прочее | `objectdb_profiler`, `interactive_music`, `noise`, `lightmapper_rd`, `csg`, `gridmap`, `vhacd`, `camera` | grep пуст; профилировщик ObjectDB — инструмент, не продукт |

**Что НЕЛЬЗЯ резать (проверено):**
- `websocket` (+`mbedtls`, `wslay`) — транспорт удалённых мест: `game/server/game_server.gd:11`, `game/ui/remote_session.gd:5`, `game/seats/drivers/remote_driver.gd:5`.
- `gdscript` — весь продукт на GDScript.
- `freetype`, `msdfgen`, `libpng`, `zlib`, `basis_universal` — шрифты/PNG/импорт.
- `regex`(`pcre2`) — используется в `game/sdk/markdown_renderer.gd` (проверить точечно перед сборкой).
- `text_server_fb` — без него текста не будет вообще (доки: «Otherwise, the compiled binary won't contain any text server»).

## 3. Чем рискуем

1. **Текст перестанет рисоваться как сейчас (этап 2).** `text_server_fb` не умеет BiDi,
   лигатуры и сложные шрифты. Если в UI есть эмодзи/японский/арабский или сложные лигатуры —
   поедут переносы и глифы. Проверка — `MOCK-01`/`MOCK-02` (визуал) + `i18n_test`.
2. **`disable_3d=yes` тянет за собой навигацию** (официальная оговорка). Сейчас навигации нет,
   но появление любого `NavigationAgent2D` в UI в будущем упадёт на сборке, а не в рантайме —
   ошибка будет поздней и «странной».
3. **Пин шаблонов перестаёт быть пином.** `tools/ci/fetch_templates.sh:14,31-40` качает
   `Godot_v4.7.2-stable_export_templates.tpz` и проверяет sha512 из релиза. Свой шаблон ломает
   и проверку, и воспроизводимость: понадобится свой артефакт + свой sha512 + хранение
   (≈ 10 МБ на вариант). Это **зона диспетчера/CI**, не исполнителя.
4. **Сборка из исходников — это emscripten + scons + часы.** Официальные шаблоны собираются
   в CI Godot с `-j`, LTO включён (`Performed in official builds: Yes` для LTO/`optimize=size`).
   Повторить LTO локально — долго и памятьёмко; без LTO можно потерять часть выигрыша
   (то есть «срезали 13 МБ» может превратиться в меньше).
5. **Рассинхрон версии движка и шаблона.** Экспорт требует, чтобы шаблон был ровно версии
   редактора (`4.7.2`); свой шаблон надо пересобирать на каждый апгрейд Godot — это постоянный
   налог, а не разовая работа.
6. **Риск «срезали не то» ровно как с `replay.gd`.** `docs/program.md:542-544` фиксирует случай,
   когда файл грузится в рантайме и «по списку лишнего» его выкидывать нельзя. Все `module_*_no`
   из §2.2 проверены grep'ом по коду, но рантайм-загрузка (`.gd`/`.tscn` в паке, `load()`)
   grep'ом ловится не полностью. Гейт-страховка: `S3` (собранный пак играется в браузере).
7. **`build/` не пересобран** — сейчас нечем даже доказать «до». Первый шаг любой такой работы —
   пересобрать поставку и записать измеренный `index.wasm`, иначе «после» будет сравниваться
   с числом из доков (а оно, как показано в §1.3, на 694 682 B больше фактического).

## 4. Ожидаемая экономия (оценка, число)

### 4.1. Метод (чтобы число можно было пересчитать)

- База: **38 820 072 B** raw / **10 111 470 B** gzip (§1.3, §1.5).
- Этап 1 (`disable_3d`): официальная цифра «about 15 %» из доков → `0,15 × 38 820 072 = 5 823 011 B`.
- Этап 2 (текстовый сервер) и этап 3 (модули): модель «доля скомпилированных исходников».
  Замер по GitHub trees `4.7.2-stable`: C/C++ исходники всех `modules/` = 12 184 393 B,
  `thirdparty/` = 112 732 225 B. Набор этапа 2 (`text_server_adv` + `icu4c` + `harfbuzz` +
  `graphite`) = 12 721 578 B → 10,18 % этого «модульного мира»; набор этапа 3 (без 3D и без
  текста) ≈ 12,6 МБ → ≈ 10,1 %. Предположение (явно): модули и их third-party дают 60–80 %
  code-секции (33 763 223 B), остальное — core/scene/servers/platform. Отсюда код:
  этап 2 = 2,1–2,8 МБ, этап 3 = 2,0–2,7 МБ. Плюс к этапу 2 — ICU-данные из data-раздела:
  0,71–4,75 МБ (измеренные границы §1.7), в центре 2,7 МБ.
- gzip-экономия считается как 26,0 % от raw-экономии (коэффициент сжатия §1.5).

### 4.2. Итог

| Этап | raw, экономия | raw, вес после | gzip после | доля от 38 820 072 B |
|---|---|---|---|---|
| **1. `disable_3d=yes`** | **5,8 МБ** | 33,0 МБ | 8,6 МБ | **−15,0 %** |
| + 2. `text_server_adv→fb` (с ICU) | +2,8…7,5 МБ (центр 5,1) | 27,9 МБ | 7,3 МБ | −28 % |
| + 3. модули (§2.2) | +2,0…2,7 МБ (центр 2,4) | **25,5 МБ** | **6,6 МБ** | **−34 %** |

**Ответ числом:** движок **38 820 072 B → оценочно 22,8–28,2 МБ raw** (центр **≈ 25,5 МБ**),
то есть **экономия ≈ 13,3 МБ raw (27–41 %, центр 34 %)**; на проводе (gzip) **10,11 МБ → ≈ 6,0–7,4 МБ**,
экономия **≈ 2,8–4,2 МБ, центр 3,5 МБ**.

Один только этап 1 (`disable_3d`, самый дешёвый и самый безопасный) даёт **−5,8 МБ raw / −1,5 МБ gzip**.

### 4.3. Погрешность — честно

- Погрешность оценки **±40 %** (модель «исходники → байты» без сборки не точнее). Реальное
  число даёт только собранный шаблон, и тогда его надо записать в документ числом.
- ICU-вклад измерен только границами (§1.7): 0,71 МБ точно, 4,75 МБ — верхняя граница.
  Поэтому этап 2 — самая неопределённая строка таблицы.
- gzip-экономия может оказаться **меньше** пропорциональной: удаляемые данные ICU — таблицы
  с низкой энтропией, они жмутся лучше кода; если считать по 26 %, экономия на проводе
  завышается. Нижняя граница по gzip — считать только code-часть.

## 5. Решение

**ДЕЛАЕМ — поэтапно, и начинаем с этапа 1.**

Обоснование:
1. Рычаг реальный и единственный оставшийся: пак уже почищен (676 612 B, `docs/program.md:552`),
   движок в 57× больше пака (§1.6) — уменьшать больше нечего.
2. Этап 1 (`disable_3d=yes`) даёт **−15 % (−5,8 МБ raw / −1,5 МБ gzip)** по официальной цифре,
   при нулевой зависимости продукта от 3D (`game/` не содержит ни одного 3D-API, §2.2) —
   это лучший ratio «эффект / риск» из всего списка.
3. Этап 2 (ICU/текст) даёт ещё ~5 МБ, но трогает то, что видит игрок (текст) — только после
   зелёных `MOCK-01`, `MOCK-02` и `i18n_test` на сборке с `text_server_fb`.
4. Этап 3 (модули) — **не делать как отдельную работу**: доки сами оценивают его как
   «Very low to moderate» при сложности «Medium to hard»; 2 МБ не стоят поддержки
   списка флагов на каждый апгрейд движка. Взять только те модули, что уже отваливаются
   от этапов 1–2 (XR/видео/кодеки — бесплатно, если флаг всё равно правится).

**Условия, без которых «делаем» не начинается (зона диспетчера, не исполнителя):**
- Сначала пересобрать поставку и записать **измеренный** `index.wasm` (сейчас `build/` нет, §1.2);
  число из программы (39 514 754 B) не воспроизводится (§1.3) и базой быть не может.
- Зафиксировать политику шаблонов: свой артефакт + sha512 + где хранится (`tools/ci/fetch_templates.sh`
  сейчас жёстко привязан к релизу Godot, строки 14, 31-40).
- Приёмка — числами: `ECO-05` (состав и вес поставки, `docs/program.md:581`) должен увидеть
  «до/после» и упасть, если вес не упал; `S3` — пак играется в браузере; `SG-10` — fps не просел.
- Оценка из §4.2 идёт в карточку как **гипотеза**, которую сборка обязана подтвердить или
  опровергнуть; после сборки число в этом разделе заменяется измеренным (правка чисел в доках —
  зона диспетчера, `docs/program.md:733`).
