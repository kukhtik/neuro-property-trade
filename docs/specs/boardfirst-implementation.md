# Внедрение Б1 «кольцо во весь кадр» в продукт

> Задание владельца 19.10: «бери самое лучшее и полностью реализуй, закрывай все хвосты».
> Основа — принятый концепт `design/variants/round2/boardfirst-1-fullring.html` и три его живых
> развития (`boardfirst-1-live-{deepseek,spacebunny,glm}.html`).

## 1. Что берём у кого (решение, а не вкус)

| откуда | что берём | почему |
|---|---|---|
| **Б1** (принят) | геометрия: кольцо занимает кадр, углы — экраны 320×190, центр — узкий хаб 720×150 | R-2 99.2 %, R-1 0.0 %, клетка 88.88 px; единственная геометрия, где glance и клетка живут одновременно |
| **deepseek** | общая шкала событий; **показ вместо слов**: сумма броска → восемь делений-шагов, владения → цифра + рельс на 4 слота, копилка → стопка монет | измерено: 4.56 % кадра в движении (самая широкая волна из трёх), знаки объявлены и легендированы |
| **space-bunny** | **свет идёт по кольцу вместе с ходом** (переход хода как физическое движение света); вуаль на паузе | это самый сильный смысловой ход из трёх: ход читается без текста |
| **glm** | акцентные вспышки на точечных событиях (покупка/аренда/залог) | 0.31 % площади при амплитуде 660: редко, но контрастно — дополняет широкую волну |
| **все три** | выключатель анимаций, который глушит **всё**, включая псевдоэлементы; `prefers-reduced-motion` = тот же выключатель | тот же баг, что мы уже починили в продукте; в CSS он ловится `*,*::before,*::after` |

**Знаки** в продукте: `×` (размер группы), `−` (списание), `·` (разделитель), `→` (переход). Это ровно
набор, который уже разрешён R-9/R-10 (`— • … →` + числа); расширение без легенды не вводим.

## 2. Требования, которые обязаны остаться зелёными

R-1 ≤ 25 % пустых ячеек · R-2 ≥ 70 % нутра · R-17 клетка ≥ 77 px · R-7 glance ≥ 12 px на телефоне ·
R-12 ни одна функция не исчезает · R-9/R-10 без значков и односимвольных подписей · R-15 рейлы
48 px в широком профиле отсутствуют · R-16 компакт скрывает только журнал.

## 3. Порядок работ (каждый шаг — свой коммит и своя проверка)

1. **Геометрия кольца.** `BoardScene`: кольцо = весь прямоугольник кадра; полосы фиксированной
   толщины; клетки прямоугольные (боковые 190×w, верх/низ w×190, углы 320×190). `TileView`
   получает явные `w/h` вместо одного `cell`; внутренние метрики считаются от `min(w,h)`.
2. **Углы-экраны.** Четыре угла несут glance: `ХОД: <имя>` · `ФАЗА: <…>` · `БАНК ПАРКОВКИ $N` ·
   `РАУНД N` кеглем ≥ 50 px на кадре 1600 (eff 12.19 на 390). Строки берутся из проекции.
3. **Центр — хаб.** Кубики + сумма 64 px + подсказка. Четыре панели (журнал, инспектор, игроки,
   событие+консоль) переезжают внутрь кольца — как в Б1, без потери функций.
4. **Анимации 11 событий** через `SkinManager.animations` (мастер-выключатель): ход (свет по кольцу),
   бросок (шаги), покупка/аренда (акцентная вспышка), аукцион, сделка, стройка (дом вырастает),
   залог (штриховка наползает), банкротство (гаснет), конец игры, пауза (вуаль).
5. **Телефон.** Кольцо не сжимается: камера даёт окно 1:1 с перетаскиванием (`board_camera`),
   glance-строки на 12 px.
6. **Хвосты** (см. §4), затем полный прогон: оракул, `run_gates.sh --all`, сборки, артефакты.

## 4. Хвосты, которые закрываются в этом заходе

- R-7 на телефоне (был worst 2.92 px, дефицит 4.10×) — закрывается углами-экранами и окном 1:1.
- R-1 тонкий запас 23.8 % — кольцо во весь кадр даёт 0.0 %.
- Верхняя панель «непонятно что там» — её роль забирают углы-экраны; шапка остаётся полосой
  управления и перестаёт дублировать факты хода.
- Три видео (старт+приглашение, админка, полная партия) — записываются на финальной сборке.
- Внешний отчёт `e2e_quiz_pilot_20261018/REPORT.md` — выводы в трекер.
- Клавиатура: вердикт по `keyboard_only_probe` фиксируется в трекере.
- Документация: `ui-integration-status.md` (новый раздел), `docs/restoration/gates.md`.

## 5. Чего этот заход НЕ делает

- Не трогает ядро/сервер/места (детерминизм и интенты остаются как есть).
- Не переносит визуал на сцены/Theme (фаза 2 программы — только по отдельному «go»).
- Не меняет правила игры.
