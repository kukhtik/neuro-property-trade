### П1.10 — аудит пайплайнов: затык найден и закрыт (SDK-таймаут)

Заказ владельца: «проверь пайплайны — сценарии как пользователи будут играть, есть ли затыки
у админа, у иишек». Админ и ИИ проверены гейтами; SDK-место проверено настоящей моделью.

**Чем мерили (новые инструменты):**
- `tools/ci/llm_seat.py` — SDK-место, которое спрашивает у модели (opencode free) одно действие из
  предложенных; логирует латентность и `FALLBACK`, режим `--silent` изображает мёртвый мост.
- `tools/ci/llm_match.sh` + `game/tools/llm_match.gd` — матч 4 места (1 SDK-модель + 3 ИИ) с
  таймером, отчётом «раунды / интенты по местам / гистограмма событий / затыки» и дампом состояния
  при затыке (фаза, pending, ожидание мест, состояние адаптера).

**НАЙДЕННЫЙ ЗАТЫК (до фикса).** `turn_timer=20`, модель отвечает 40–120 с. Матч встал на
`TURN_START`, ход места 0, `pending=null`, место ждало **120.7 с** при окне 20 с, `away=false`:
```
MATCH stall-state phase=TURN_START turn=0 pending=<null>
MATCH stall-settings turn_timer=20 auction_timer=15 timeout_action=auto-pass
MATCH stall-seat pid=0 driver=SDK waiting=120.7s away=false
```
Причина: менеджер мест **намеренно** не авто-пасует SDK («гонка с адаптером»), а у адаптера таймаута
не было — в коде стояло «a future SDK-side timeout (one short retry then auto-pass, per spec)».
Мост молчит → матч висит вечно, а часы в шапке продолжают идти.

**Фикс** (`game/sdk/sdk_adapter.gd`): `_tick_await()` — на 1× окно (свой счётчик аукциона в фазе
`AUCTION`) один повторный force, на 2× — минимальное легальное действие места
(`seats/minimal_action.gd`). При `turn_timer=0` (реплей/soak) ничего не меняется.
Первая редакция фикса не работала: повтор сбрасывал флаг повтора, и цикл «re-force каждое окно»
не доходил до авто-паса — теперь флаг снимается только в `emit_events` (действие выполнено).

**Доказательство (мёртвый мост, `--silent`):**
```
ДО фикса   MATCH DONE rounds=1 log=11 stalls=3   ==> LLM-MATCH STALLED
ПОСЛЕ      MATCH DONE rounds=1 log=69 stalls=1   ==> LLM-MATCH ADVANCING
           (место таймаутится и авто-пасуется, матч не замер)
```
`HG-08` (быстрый мок) — **PASSED**: быстрый SDK-игрок не задевается. Оракул `411 tests, 0 failed`.

**Живая модель, таймер выключен:** `space-bunny-free` — 4 раунда, 33 принятых интента SDK-местом,
5 аукционов (50 ставок), 0 затыков; ИИ-места 34–48 интентов каждое. Медиана решения **50.8 с**,
`FALLBACK` 3 из 8 (модель иногда отвечала прозой).

**Ограничение, которое видно сразу:** движок держит **одно SDK-подключение на процесс**
(`seat_config.gd`: второй `sdk:` уходит в ИИ). Поэтому «несколько моделей за столом одновременно» в
одном процессе невозможны — харнесс гоняет модели по очереди, а не сажает их в один матч.

**Админ и ИИ — зелено:** `HG-02` (12 нажатий консоли, 0 отказов по вине UI), `HG-12` (админ-панель,
F12, токен-гейт, стрим-роль, наблюдатель без ввода), `HG-13` (таймер тикает, скрывается, срабатывает).

Грабли харнесса (чтобы не повторять): `opencode run` принимает сообщение МАССИВОМ позиционных
аргументов — многострочный промпт доезжает одной вводной фразой; stdout модели надо писать в ФАЙЛ,
не в пайп, иначе `timeout` на Windows ждёт внуков node (замер: кап 45 с дал 78 с).

### П1.11 — мульти-SDK: несколько SDK-мест в одном процессе

Было: `seat_config.resolve_driver` понижал ВСЕ `sdk:`-места после первого до ИИ. Причина — вендорный
аддон был однопоточным по соединению: `Websocket._ws_write()` писал очередь ЛЮБОГО экземпляра в сокет
автолоада, а `NeuroActionHandler` держал ОДИН глобальный реестр действий по имени (второе место
затирало `roll_dice` первого).

Сделано:
- **Соединение на место**: `sdk_adapter` при наличии endpoint создаёт СВОЙ экземпляр
  `addons/neuro-sdk/websocket/websocket.gd` (`ws_url_override`), и `_ws_write` пишет в свой сокет.
  Без endpoint — прежний путь через автолоад (совместимость с HG-08).
- **Реестр действий на соединение**: `NeuroActionHandler` теперь `handler_for(conn)`; `CommandHandler`
  (он создаётся на каждый websocket) помечает, на каком соединении пришло сообщение, поэтому
  `get_action("roll_dice")` разрешается в действие ИМЕННО этого места.
- **Результат и force идут по своему соединению**: `ActionWindow.conn`, `EngineAction.connection()`,
  `ActionResult` через `action.connection()`, `Context.send(..., conn)`.
- **Настройки**: `sdk_endpoints` (список ws-адресов, по месту), `seat.sdk_endpoint`,
  `resolve_driver(..., has_endpoint)` — место со своим endpoint получает драйвер SDK, без endpoint
  второй `sdk:` по-прежнему уходит в ИИ (честное ограничение: один сокет = один персонаж).

**Замер (гейт `MULTI-SDK`, два мока, один процесс):**
```
MULTI-SDK seats: 2 SDK of 4 (Seat A=SDK, Seat B=SDK, Bot 3=AI, Bot 4=AI)
MULTI-SDK connection pid=0 node=SdkConn0 connected=true
MULTI-SDK connection pid=1 node=SdkConn1 connected=true
MULTI-SDK intents pid=0 accepted=6 · pid=1 accepted=7
==> MULTI-SDK PASSED (2 connections, round 1)
```
Регрессия однопоточного пути: `HG-08 PASSED` (один SDK через автолоад, 4 места, матч идёт).
Оракул: `ran 414 tests, 0 failed`. Гейт добавлен в `run_gates.sh` карантином.

Побочная находка: вендорное `ActionWindow` отправляет FORCE только когда `_timer >= _force_timeout`,
то есть **сила задерживается на величину окна** — при `turn_timer=0` уходит сразу. Это объясняет,
почему старые гейты (с таймером 0) не замечали задержки; в реальном матче с таймером 30 с первое
приглашение приходит через 30 с. Записано как долг.

### П1.12 — демо-запись: три SDK-игрока, видео и действие из админки

Заказ владельца: «запустить новый смоук на нескольких SDK (3 игрока), записать видео, ходы не
мгновенно (≥1 с), и показать всё приложение, включая действие из админки».

Инструменты:
- `tools/ci/demo_multi_sdk.sh` — поднимает ТРИ `llm_seat.py` (у каждого `--pace 1.2`, поэтому каждое
  решение и ход виден не меньше секунды), запускает приложение **окном** и собирает кадры в MP4
  (ffmpeg из комплекта агента).
- `game/tools/demo_multi_sdk.gd` — сценарий демонстрации; кадры снимаются из вьюпорта приложения
  (то же, что делают SG-03/SG-07), в JPEG (PNG давал ~3 fps и рывки, JPEG держит 10 fps).
  Таймлайн: доска (клик по клетке → инспектор), кнопка «Панели» (сайд-панели убираются и
  возвращаются), админ-панель открывается, **ПАУЗА**, **Продолжить**, панель закрывается.

**Найдено и починено этим демо (реальные дефекты, не косметика):**
1. **Роутинг действий по «текущему» соединению.** `NeuroActionHandler.get_action()` отвечал по
   соединению, которое говорило ПОСЛЕДНИМ; адаптер, собирая своё окно, мог взять действие ЧУЖОГО
   места, и его ход исполнялся у другого («not your turn» у места, чей ход как раз был). Добавлен
   `get_action_on(conn, name)`; адаптер теперь берёт действие своего соединения. До этой правки
   из трёх SDK-мест играло одно.
2. **Админ-панель падала на токен-гейте**: `_host_name()`/`_current_timer()` читали
   `_controller.engine`, а панель держит ГЕЙТ (`admin_gate.gd`), у которого движка нет —
   `SCRIPT ERROR: Invalid access to property or key 'engine'`. Появился `_engine()`, который
   проходит на уровень вниз.

**Замер (гейт-видео, 52 с):**

DEMO seat Bot driver=AI intents=41 · SDK 3=9 · SDK 2=5 · SDK 1=7
DEMO events=63 pause/resume=2 frames=521

меняется 14.7 % пикселей (то есть в кадре действительно живой интерфейс, а не статика).

### П1.13 — моргание таймера и «боковые кнопки маленькие» (по докладу владельца)

1. **Таймер моргал.** Причина найдена: поля таймера (`timer_window/elapsed/active`) добавлял только
   спектаторский путь `seat_manager.emit_spectator`, а `for_player` их не нёс вообще. Оболочка
   хранит проекцию то из одного источника, то из другого — и на каждом «бедном» кадре
   `_timer_on` становился false, часы прятались, а на следующем кадре возвращались. Теперь
   `projection._timer_view()` даёт эти три ключа И месту, И наблюдателю (одно место правды), а
   `top_bar` вообще не стирает часы, если проекция их не принесла.
2. **Боковые кнопки.** Рейл-панели теперь делят высоту стороны пополам
   (`SIZE_EXPAND_FILL`), кегль повёрнутой подписи 13 → **18**:

```
было   rail-right-journal   48×28     rail-right-inspector 48×28
стало  rail-right-journal   48×557    rail-right-inspector 48×557   (сторона 1120 px заполнена)
```

Проверки после правок: `ран 414 tests, 0 failed`, `SG-01/02/04/05/11 PASSED`, `TIMER ... STABLE`.

**Заведён документ второго круга** — `docs/specs/ui-redesign-round2.md`: задание на редизайн клеток
доски (на телефонном кадре уже не помещается), верхней панели и живости/анимаций, с чек-листом трёх
будущих видео (старт и приглашение · админ-панель · партия целиком) и с правилами из внешнего
прогона e2e (уникальный признак в цели автотеста; «выглядит нормально» и «есть куда идти» — разные
проверки).

### П1.15 — R-7 измерен на том, что нарисовано (гейт перестал судить невидимое)

Гейт STREAM-READ судил `jrn-title`/`jrn-text` — а это узлы правого дока, который **скрыт** во всех
кадрах уже́ 2000 px (компактный режим; истинно и при 1600×1200, и при 1920×1080). То есть вердикт
гейта описывал элемент, которого в кадре нет, а панно — то, что на экране — имён не имело вообще.

Что изменено:
- панно даёт имена своим glance-меткам: `panno-turn`, `panno-event-text`, `panno-jrn-text`;
- GLANCE_SET гейта теперь содержит **нарисованный** набор, а док-журнал помечен `drawn_only`:
  если он скрыт, строка печатается как «NOT DRAWN … not judged», а не вершит вердикт;
- строка «не нарисовано» не попадает в суждение, но и не молчит (в логе она есть).

Числа после правки (кадр 1920×1080, телефон 390 px, порог 12 px эффективных = 59 px в кадре):

```
panno-turn       22 px → 4.5 px    panno-event-text 22 px → 4.5 px
panno-jrn-text   16 px → 3.3 px    шапка (turn-name/phase, round, pot) 13 px → 2.6 px
jrn-title/jrn-text  НЕ НАРИСОВАНЫ (док сложен) — не судятся
==> STREAM-READ FAILED: the smallest glance label is 2.6px on a phone
```

Вывод, который надо принять в редизайн: **R-7 нельзя закрыть правкой кегля** — нехватка 2.6–4.6×,
и в шапке 59 px вообще не помещаются (полоса 56 px). Значит glance-слой должен жить в панно
(там есть высота), а шапка — быть полосой управления, а не носителем glance. Это задача B/C
второго круга (`docs/specs/ui-redesign-round2.md`), числа выше — её вход.

### П1.14 — две пробы от субагентов (эксперимент «я + beam-субагенты»)

Обе задачи ушли субагентам (`deleg_9725cfae`, канал `opencode-go` + `deepseek-v4.1-flash`), обе
вернулись артефактами, обе прогнаны **мной** — их самоотчёт здесь подтверждён, не принят на веру.

**1. `tools/ci/r7_report.py` + `build/r7/r7-report.md` (R-7, офлайн-половина).**
Мой прогон совпал с их цифрами: кадров 40 (28 живых), живые — 1600×1200 (×26) и 880×600 (×2);
масштаб к 390 px = 0.244; требуемый кегль в кадре **49.2 px**, сегодняшние 12 px дают **2.92 px**
(нехватка **4.10×**); хуже всех «заголовок журнала». Важный побочный вывод: в кадрах 1600×1200
**журнал вообще не нарисован** — `game_view._is_compact()` истинно (1600 < 2000), правый док
скрыт, а гейт STREAM-READ читает `jrn-title`/`jrn-text` из невидимых узлов: его число верное, но
описывает элемент, которого в стартовом кадре не видно. Порядок правок по R-7: журнал → шапка →
доска (замер на 4 профилях, чтобы читаемость не оплачивалась размером клетки).

**2. `game/tools/keyboard_only_probe.gd` (партия только клавиатурой).** Ответ на вопрос владельца
«есть ли полная возможность играть только клавиатурой» — **да, и вот доказательство**:

```
==> KEYBOARD-ONLY PASSED (a LOCAL human seat rolled the dice with the app's own Space binding,
    Tab and the arrows move the focus, Space presses a focused control, the match reached round 2,
    0 mouse events)
```
(a) Tab/стрелки двигают фокус (5 контролов: Настройки, Панели, Заново, Язык, Тема);
(b) **Space катит кубики** через собственный биндинг приложения (журнал движка +1 `roll`), при
отпущенном фокусе — иначе Godot отдаёт Space кнопке;
(b2) Space нажимает сфокусированный контрол и панели реально прячутся (`panels_hidden false→true`);
(c) партия дошла до раунда 2 при `round_limit 3`; мышиных событий — 0.

Найдено по ходу: **первая редакция пробы не могла ответить на вопрос** — на столе из четырёх ИИ
`_human_pid = -1`, консоль не рисует кнопок, и клавиатурный бросок запрещён *по замыслу* (HG-12);
проба падала «no roll». Лечится посаженным LOCAL-местом. Второе: **один полный тап (press+release)
активирует сфокусированную кнопку шапки ДВАЖДЫ** (`button_down`/`button_up` — по одному,
`pressed` — два, `action_mode=1`), поэтому переключение панелей «не срабатывало» — чётное число
переключений. В пробе обойдено нажатием без отпускания; это записано как отдельная находка для
разбора в продукте (кнопки шапки можно нажать клавиатурой — но визуально это no-op).
