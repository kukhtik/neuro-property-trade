# UI-паспорт — «глаза и описание» интерфейса для агента

> Зачем: гейт отвечает «прошло/нет» и ничего не говорит агенту о том, **что на экране**.
> Паспорт — не гейт: он описывает. Один прогон даёт по каждому состоянию и профилю
> машинное дерево, текстовую карту всего экрана, кадр и (по запросу) фильм движения и
> поведения. Дальше агент читает `build/ui-passport/for-agent.md` и «видит» интерфейс
> целиком — без догадок и без единственного скриншота.

## Команда

```bash
tools/ci/ui_passport.sh [--skin=neuro] [--with-stream] [--film] [--save-baseline] [--diff]
```

Вердикты читаются строками: каждый прогон печатает `UI PASSPORT DONE seq=<seq> states=<n>`;
любой `SCRIPT ERROR` (с двоеточием) валит раннер; итог — `==> UI PASSPORT OK (N states)`.
Досье: `build/ui-passport/for-agent.md`.

## Что получается

| Артефакт | Что это |
|---|---|
| `for-agent.md` | **весь интерфейс словами**: таблица состояний + по каждому — регионы, тексты в порядке чтения, кегли, флаги (вне экрана / обрезано / мелко) |
| `*.tree.json` | то же машинно: узел = id, класс, прямоугольник, текст, кегль, цвет, тултип, `clip_chain` |
| `*.text.md` | текстовая карта одного состояния (входит в досье) |
| `annotated_*.png` | кадр, размеченный из ЭТОГО ЖЕ дерева: жёлтые рамки — регионы, голубые — текст, красные — мелкий/обрезанный (Pillow: `py -3.12`) |
| `report.html` | то же для глаза: кадр + разметка + текст |
| `film_<profile>.motion.json/.md` | **фильм**: что двигалось (rect/alpha/rotation/scale), что появлялось, таймлайн фаз и **отклик на каждое действие** |
| `diff.md` | **что изменилось** против baseline: добавленные / удалённые / изменённые узлы и поля |

Покрытие состояний: `pre` → `cold`, `settings`, `join-none`; `match` → `turn-human`, `trade`,
`inspector`, `purchase`, `ai`; `--with-stream` добавляет те же человеческие состояния в
роли `stream` (1280×720); `--film` записывает движение и поведение. Состояния, требующие
ввода, в наблюдателе недостижимы — это норма, а не MISS.

## Фильм: анимации и поведение

`--film` запускает сэмплер (50 мс): геометрия, прозрачность, поворот и масштаб каждого
Control + фаза движка. Скрипт сам помечает свои действия (бросок, модалка) и прогоняет их
через настоящие швы. Итог — `film_<profile>.md`. Проверенный пример из прогона:

```
- roll @61ms: успокоение 1494ms
Фазы: TURN_START @0ms → PURCHASE_WAIT @815ms   (движок ответил через 754мс — это анимация кубиков)
- …/stage/@HBoxContainer@148/@Control@150  rect  [687,410,40,40] -> [671,382,37,42]  (1446ms)
```

Фильтр: пересборка плиток борда на каждый push состояния — не анимация, она отброшена;
модалки/тосты/баннеры (именованные узлы вне борда) остаются. Анонимный чарн в отчёт не льётся.

## Дифф: что изменилось

```bash
tools/ci/ui_passport.sh --save-baseline     # снять эталон
tools/ci/ui_passport.sh --diff              # прогнать и сравнить с эталоном
```

Ключ — путь узла без авто-нумерации (`@NNN`), поэтому переименованный или удалённый контрол
виден как `+`/`-`. Прямоугольники сравниваются с допуском 1px (микро-сдвиги отдельно),
текст/кегль/цвет/тултип/клип/регион — точно. Без baseline дифф честно падает, а не печатает
«ноль изменений». Проверено: два прогона подряд — нули; смена кегля 9→14px — поймана.

## Веб-производитель (тот же контракт)

Контракт один, производителей два: Godot (`game/tools/ui_passport.gd`) и веб
(`web_passport.py`, Playwright). Оба пишут `<state>_<profile>.tree.json` + кадр, поэтому
отчёт, досье и дифф работают для сайта без единой правки:

```bash
py -3.12 web_passport.py --url=https://site --name=home --out=passport --viewport=1440x900
py -3.12 web_passport.py --url=https://site --name=menu --out=passport --film=3 --actions=acts.json
py -3.12 ui_passport_report.py <repo> --dir=passport            # for-agent.md + annotated_*.png
py -3.12 ui_passport_diff.py  <repo> --dir=passport --baseline=passport/baseline
```

Дерево для сайта — DOM (rect / собственный текст / font-size / color / overflow / landmarks
вместо Control), фильм — те же события из `getBoundingClientRect` / opacity / `transform`,
а «фазы» — URL и заголовок. Проверено на трёх целях: локальная тест-страница (фильм поймал
CSS-переход: клик → alpha панели 22→100 за 347 мс, спиннер в движении 40 сэмплов), внешний
сайт `example.com`, тяжёлая страница прототипа NPT (875 узлов, 414 текстов, 9 обрезанных,
214 мелких, min_font 6).

## Ритуал агента (как этим смотреть)

1. Прочитать таблицу в `for-agent.md` — сразу видно, где `вне экрана / обрезано / мелко > 0`
   и какой min кегль у состояния.
2. Взять `annotated_<state>_<profile>.png` — это и есть «увидеть»: где регионы, где текст.
3. Уточнить геометрию/цвета/текст в `*.tree.json` (`id`, `path`, `x/y/w/h`, `fs`, `col`).
4. Проверить по чеклисту:
   - все ли регионы на месте и на своих местах (сравнить с `design/regions.json`);
   - нет ли текста вне экрана, обрезанного или ниже пола своей роли;
   - говорит ли состояние то, что обещает (аукцион — часы и лот; сделка — имена клеток;
     аренда — «сейчас»; панели — без мёртвых зон);
   - совпадает ли текстовая карта с кадром (язык, числа, имена).
5. Никогда не судить по одному кадру: структура (JSON) — доказательство, кадр — иллюстрация.
   Когда важен отклик — `film_<profile>.md`; когда правка — `diff.md`.

## Границы (честно)

- Headless-раскладка точна только потому, что размер корня прибит (`--size=WxH`); масштаб
  ОС/DPI в дампе не отражён.
- Кадры игры приходят из серии SG-07 (`build/renders/<state>_<skin>.png`); у веб-производителя
  кадр лежит рядом с дампом. Кадр другого размера не подставляется — пишется «другой размер».
- Паспорт **ничего не валидирует**: «красные флаги» — повод посмотреть, вердикт — у гейтов.
- Негативная проверка инструмента: испортить кегль в скине → в досье растут `мелко`/`min_font`
  у всех состояний; вернуть — снова ноль. (Прогонять при правках самого паспорта.)

## Как это переносится на другой проект

Схема универсальна: **одна команда → по каждому состоянию и профилю (пиксели + дерево +
текстовая карта + разметка из тех же данных [+ фильм] [+ дифф]) → один файл-досье**.
Для Godot дерево даёт `Control.get_global_rect()`/`get_theme_font_size()`; для веб — DOM-дамп
(Playwright `evaluate`).
Правило одно: **описание и картинка обязаны происходить из одного источника**, иначе
разметка однажды начнёт врать (в этом репо так уже было дважды).
