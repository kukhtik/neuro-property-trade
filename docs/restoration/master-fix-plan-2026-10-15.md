## 1. Трек READ — «доску и панели можно прочитать» (D1–D7)

**Почему это первый приоритет.** Две фазы редизайнов отладили структуру и
палитру, но ни один гейт не измерял размер текста и заполненность панелей —
«зелено» означало «нарисовано», а не «прочитано». Стрим с такими кеглями не
работает при любом скине.

### R-1 — Клетка читается (D1–D4)

**Правило нового рендера клетки** (`tile_view.gd`):
1. Имя — всегда `short` из записи (D3): поле уже в проекции; fallback — `name`.
2. Шрифт имени: `maxi(11, mini(13, int(c*0.17)))` — нижний порог 11px вместо 8
   (при cell 63.6 это 11px; `short`-имя «Harbor Stn» при 11px ≈ 55px — влезает).
3. Цена: `maxi(9, mini(11, int(c*0.13)))` — 9px пол вместо 7.
4. Дома: текстовый счётчик «×N» (или «⌂N») 10px на полосе группы рядом с
   квадратами; отель — «H»/«⌂×5». Квадраты остаются как дублирующий визуал.
5. Бейдж владельца: `maxi(12, c*0.20)`, буква — 9px минимум.
6. Подключить `label_step` (D2) к board_scene: step по cell; на step 3 (cell<44)
   имя скрыто, но цветовая полоса группы и бейдж владельца остаются — клетка
   остаётся различимой, а инспектор/тултип дают имя.
7. `clip_text` на имени заменить на OVERRUN_TRIM_ELLIPSIS + тултип с полным именем.

**Тесты:**
- `tile_view_test`: при cell 63.6 — имя = short, font_size ≥ 11; при cell 40 —
  имя скрыто, полоса+бейдж есть (шаг 3); счётчик домов на полосе соответствует
  `houses`; negative: вернуть clamp 8 → тест падает «font 9px».
- Новый гейт **READ-01** (кадровый, образец SG-07-машинерии): кадр 1440×900
  живого матча → по каждой из 40 ячеек кольца «есть различимый идентификатор» =
  текст ≥10px высотой ИЛИ цветовая полоса+бейдж; количество молчащих ячеек ≤ 2
  (углы — спец-иконки). Вердикт: `==> READ-01 PASSED (38/40 ячеек идентифицируемы, кегль 11px)`.
  Негатив: вернуть 9px-шрифт → ровно READ-01 краснеет с числом ячеек 32.

### R-2 — Панели без пустот (D5, D6)

**Правило:** док обязан распределять контент по высоте, а не наливать сверху.
1. Левый док (`players_panel.gd`): список карточек получает EXPAND_FILL,
   карточки растягивают внутренние отступы при малом числе игроков (4 места —
   равномерно по доступной высоте); статистика и ownbar — сразу после списка,
   а не прижаты в низ (AnchorLayout → порядок: заголовок, список, статистика,
   ownbar, СПИСОК ТЯНЕТСЯ).
2. Правый док: инспектор получает фикс. высоту по содержимому (~220px), журнал
   занимает всё остальное; пустой журнал показывает дружелюбное состояние
   (уже есть) по центру своей зоны, а не в первой строке.
3. Минимум живого контента: при <N событий журнал показывает «ждём первых
   событий — правила и ставки появятся здесь» с мини-легендой символов.

**Гейт READ-02** (по кадрам SG-07-механики, 4 профиля): доля «мёртвой зоны»
(подряд идущих строк без контента) внутри каждого дока ≤ 25% высоты дока;
инспектор занимает ≥ 120px только своим содержимым. Негатив: вернуть
прижатую статистику → READ-02 краснеет «левый док 60% пустоты».

### R-3 — Кегли UI (D7)

1. Скины: `size.m` 13→14, `size.s` 12→13, `size.xs` 10→11 (все 4 skin.json,
   `check_package` подтверждает синхрон с макетом).
2. Компакт-уполовинивание `text_scale 0.92` из LayoutProfile УДАЛИТЬ из
   потребителей (если найдутся) — «крупно, но не слишком» запрещает ужимание.
3. Stream-масштаб (см. STRM-01 ниже) применяет 1.15 поверх новых баз.

**Гейт READ-03:** замер по кадру: x-height строк в доках ≥ 10px при 1440×900;
`min(font_size)` в живом дереве ≥ 11 (кроме allowlist: бейдж-буквы, тикер).
Негатив: вернуть size.m=13 → краснеет с адресом фабрики.

## 2. Трек EV — «события и состояния видны» (D8–D13)

### E-1 — Сделка в именах клеток (D8, D9)

1. `modal_host.show_trade_response`: вместо «$X + N тайл(а)» — два блока-списка
   «Отдаёт: Harbor Stn, Palm Row + $200 / Просит: $150 + Chest» (имена через
   `proj.board[]` lookup по индексам из `pending.give_tiles/want_tiles`; cash
   первой строкой). Строка `modal.trade_terms` заменяется на заголовки блоков.
2. `journal_lines`: `trdoffer`/`trade` получают состав — «делает предложение:
   → Harbor Stn + $200 ⇄ Palm Row»; «сделка заключена: A ⇄ B (+$100)».
   Ключи `jrn.ev.trade*` расширяются (оба языка, `coverage.md` §4 — тем же
   коммитом; HG-09 живой проход проверит sentinel'ы).
3. Тост «Сделка завершена» → «A ⇄ B: Harbor Stn + $200 ⇄ Palm Row».

**Тесты:** `modal_trade_test` (новый): модалка входящей сделки содержит ВСЕ
имена клеток из pending, а не числа; negative: подменить рендер на счётчик →
падает с «ожидалось имя клетки, найдено '2 тайл(а)'». **EV-01** (гейт):
сценарий HG-04 прогоняется и в кадре инспектируется модалка + строка журнала —
оба содержат имя первой клетки сделки.

### E-2 — Событие видно на доске (D10)

Центральный баннер — уже существующий `_banner` в `board_scene` — становится
событийным: очередь сообщений с автоскрытием (3с), крупный кегль (18–20px).
Отображаемые события: `purchase` («N bought «X» за $Y»), `auction_start`,
`auction_win`, `build`, `bankrupt`, `jail`, `winner`, `tax`, `go_bonus`,
`trade`. Плюс вспышка клетки-участника (переиспользовать state-frame: 1с
пульсация рамки цветом события). Формулировки — те же ключи `event.*` (уже
переведены), источник — `EventAdapter`-спан, чтобы журнал/тост/баннер
говорили одно и то же.

**Тесты:** `board_event_test`: inject `purchase` → `_banner.text` содержит
имя клетки и владельца, клетка во «вспышке» (state-frame active); через
таймаут баннер погас; negative: убрать ветку события → падает «баннер не
изменился». **EV-02** (гейт): 6 событий инжектятся в живой матч, каждый
оставляет (баннер ИЛИ кадр-вспышку) + строку журнала + тост — «след в двух
зонах» (минимум). Кадры складываются в отчёт SG-07.

### E-3 — Стоимость/аренда (D11)

1. Тултип клетки (уже существует механизм `[data-tip]` в макете, в игре —
   tooltip у TileView): имя, группа, цена, ТЕКУЩАЯ аренда (с учётом домов и
   монополии ×2 — формулу берёт из проекции новое поле `rent_now`, которое
   `projection.gd` считает по тем же правилам, что движок при оплате; источник
   один — движок, UI только читает).
2. Инспектор: строка `ins.rent` уже есть; добавить `ins.rent_now` («сейчас»)
   если отличается от базовой.

**Тесты:** `projection_test`: `rent_now` на монополии с 2 домами = базовая ×
множитель домов; negative: сломать формулу → тест с таблицей ожидаемых
аренд падает. **EV-03**: кадр с тултипом открытой клетки содержит «$»
аренды ≥ 2 раза (базовая+текущая) или отчётливо помеченную текущую.

### E-4 — Аукцион виден (D12)

1. В модалку аукциона — таймер-кольцо/остаток (`pending.timer_*` уже приходят
   в проекцию для хода; расширить `_pending_view` аукциона таймером — источник
   тот же seat_manager).
2. Центральная плашка при `phase == AUCTION`: «АУКЦИОН — Harbor Stn — $310 —
   лидер Neuro» на весь центр (баннер из E-2), обновляется каждым `bid`.
3. Журнал уже пишет ставки; тост — при старте.

**Тесты:** `auction_ui_test`: pending с `high/high_player/timer` → модалка
показывает кольцо и остаток; баннер обновился после inject `auction_bid`;
negative: убрать таймер из проекции → падает «кольцо отсутствует». **EV-04**
вбирает EV-02 для аукциона (строка в таблице покрытия).

### E-5 — Имущество игрока (D13)

1. Тултип карточки места (F-11 доводится до кода): список владений именами
   клеток с цветом группы, дома/залог суффиксами, деньги, карты тюрьмы.
2. Клик по карточке — выделение клеток игрока на доске (owner-рамки остальных
   глушатся, свои — кольцо). Данные — `players[].tiles` (уже в проекции).

**Тесты:** `players_tooltip_test`: тултип содержит имена всех клеток из
`tiles[]`; выделение подсвечивает ровно их; negative: скрыть список → падает.
**EV-05**: кадр с открытым тултипом — имена ≥2 клеток читаемы (кегль ≥11).
