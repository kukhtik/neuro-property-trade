## 1. A — Twitch-чат как единая сущность (задача 1)

**Собрано и работает.**
- `game/seats/drivers/chat_driver.gd` — majority-агрегатор (окно 8 голосов,
  нелегальные молча игнорируются, ничья = первый в очереди). Юнит-покрытие в seats_test.
- `seat_manager.push_chat(pid, action, params)` — единственный вход.
- Драйвер «CHAT» выбирается в оверлее настроек (settings_overlay DRIVERS).
- HG-06 доказывает: проекция до браузера и интенты до движка по сети идут.

**Мёртвая линия:** `rg push_chat game` => ровно 1 hit (сам метод). Ингеста нет:
Twitch IRC нигде не упомянут; в `game_settings.gd` нет `chat_mode` (спека Блок 5
заявляет majority / first-command / moderator-weight; majority уже в драйвере,
осталось зафиксировать настройкой).

**Работа (по шагам, каждый — свой коммит):**
1. `chat_mode` в `game_settings.gd` + строка в оверлее «Темп» (рестарт-тег по правилу `_h`).
2. `game/tools/twitch_bridge.gd` — клиент чата (Twitch IRC через wss, либо IRC-socket):
   коннект по каналу, парс команд (`!npt buy/pass/bid 500/build 6/...`), анти-флуд,
   маппинг команда => (action, params) по легальному словарю движка.
3. Каждая распознанная команда => `seat_manager.push_chat` (чисто транспорт:
   движок всё равно валидирует, ингест не может сломать детерминизм).
4. OAuth-токен канала НЕ печатать в приглашении и НЕ логировать (по примеру seat-токена).

**Приёмка — гейт CHAT-01 (карантин -> required):**
- Матч CHAT+AI+AI+LOCAL фиксированным сидом; ингест подменяется скриптовым фейком
  (без интернета, тот же интерфейс `command -> push_chat`).
- Ассерты: 8 голосов (5x buy / 3x pass) => покупка совершена majority; нелегальный
  bid (меньше high) не дошёл (счётчик отсечений >= 1); `bid 600` => params.amount=600
  точь-в-точь; матч доведён до END_GAME при CHAT-месте в составе.
- Негатив: потеря соединения чата => CHAT-место уходит в auto-pass по таймеру

## 4. D — Пауза (задача 4): всем, Vedal — может отключить

**Сейчас:** паузы нет (admin_panel: 0 упоминаний pause/resume; admin_override —
16 операций без pause). seat_manager._process тикает по POLL_INTERVAL, поэтому
«заморозка» = перестать тикать таймеры и не пускать интенты кроме pause-управления.

**Работа:**
1. Движок: `engine.paused: bool` (НЕ входит в snapshot — пауза не игровое
   состояние, иначе реплеи сломаются) + admin_override-операции `game_pause` /
   `game_resume` (источник: admin | local; оба пишутся в event log — инвариант
   spec §4.1 «admin edits go through the engine» сохраняется).
2. seat_manager._tick: `if engine.paused: return` — таймеры стоят, объявления
   away не происходит; resolve-цикл замирает в текущей фазе.
3. Проекции: `paused: true` в for_player/for_spectator (+ source) — UI рисует
   крупный баннер «ПАУЗА» в зоне stage, таймер-кольцо стоит; журнал получает
   запись (SG-06 не сломается — пишет событие паузы как обычное).
4. Кнопки: у LOCAL-места в консоли и в админ-панели; в `--stream` кнопки нет
   (ввод мёртв по HG-12 — это остаётся).
5. Настройка `allow_pause` (вкладка «Темп», live-тег): false => кнопка у LOCAL
   исчезает и интент от non-admin отклоняется с человеческой причиной
   («пауза отключена ведущим»); админ-панель (F12) паузит всегда — Vedal
   единственный, кто может отключить паузу для всех (ваша формулировка).
6. SDK: во время паузы не слать новый force (guard `_awaiting_result` уже стоит;
   дополнительно гейт проверит отсутствие force-спама во время паузы).
7. i18n: когда пауза станет фичей наблюдателя, переписать подпись
   «Паузы нет — матч живёт по таймерам».

**Приёмка — гейт HG-15:**
- Матч SDK+AI+LOCAL: pause от LOCAL => engine.paused, decision_waiting не растёт
  (замер за N секунд), баннер в stage виден, кольцо таймера стоит;
  snapshot до/после паузы byte-в-byte равен.
- F12-панель тоже паузит; `allow_pause=false` => у LOCAL кнопки нет, интент
  отклонён с причиной, F12 работает.
- Resume возвращает ту же фазу без дублей: следующий ход уходит, матч
  доходит до END_GAME.
- Негатив: временно разрешить non-admin pause при allow_pause=false => ровно
  HG-15 падает с причиной.
- `==> HG-15 PASSED (пауза стоит, snapshot равен, allow_pause честный)`.

## 7. Порядок работ (зависимости, не календарь)

1. **D-пауза** (HG-15) — самый дешёвый пункт, закрывает «нет паузы» полностью;
   заодно снимает честную подпись «паузы нет».
2. **A-Twitch-чат** (CHAT-01) — двигает главную ценность стрима, не требует
   внешних зависимостей (мок-интерфейс позволяет разрабатывать без сети).
3. **C-1 stream-профиль** (STRM-01) — дешёвая, видимая глазу, поднимает
   «понятно зрителю с маленького экрана стрима».
4. **C-2 zoom/скрытие панелей** (ZOOM-01) — заметная фича стрима, средняя цена.
5. **C-3 voice-индикатор** (VOICE-01) — зависит от B для разделения Neuro/Evil;
   до B можно с фолбэком по driver_label.
6. **F-токены** (TOKEN-01) — параллельная ветка, никак не пересекается с сетью.
7. **B-evil коннект** (HG-14) — ждёт живого второго SDK-сервера (внешний блокер).
8. **E-бюджет 60** (правка SG-10) — финалирующая: после C-2 (новая камера может
   съесть кадров), до required-повышения — 2–3 зелёных прогона.

проверка до «готово»); `tools/ci/*.sh` — 100755; правка реестра гейтов — только
вместе с `bash -n`; MIN_TESTS менять только вместе с реальными тестами;
документ статуса обновлять тем же коммитом, где работа.
