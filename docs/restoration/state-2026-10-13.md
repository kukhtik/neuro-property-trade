## 3. Что сломано (карта, с адресами в коде)

### 3.1 Сеть: join-by-link и приглашение — заглушки
- `game/main.gd:114–117` — при наличии seat-ссылки только `push_warning("join-by-link is
  not wired in the v3 interface yet")`; `_join_as_remote()` существует, но не вызывается никем.
- `main.gd:545–587` — `_open_join_lobby()`, `_on_host_invite()`, `_show_invite()`,
  `_add_perf_overlay()` — четыре `push_warning`. Экраны `join_lobby.gd` / `host_invite.gd`
  лежат в архиве (158 и 120 строк — вернуть есть что).
- `settings_overlay` **не содержит кнопки приглашения** и сигнала `host_invite_requested`
  (main.gd:522 проверяет его через `has_signal` — на новом оверлее сигнала нет).
- Следствие: **«1 игрок vs 1 игрок на разных машинах» невозможен** — ни хост не может
  пригласить, ни гость подключиться.

### 3.2 Консоль действий: половина кнопок не может сработать
`game/ui/action_panel.gd:224–225` — все кнопки шлют `action_requested(act, {})` (пустые
параметры), а движку нужны `tile` / `amount` / `to,give_tiles…` / `accept`:

| Кнопка (когда легальна) | Что происходит | Причина в движке |
|---|---|---|
| `roll`, `buy`, `pass`, `pay`, `use_card` | работают | параметры не нужны |
| `build_house`, `sell_house`, `mortgage_property`, `unmortgage_property` | **отказ всегда** (только инспектор с выбранной клеткой умеет) | `engine.gd:462–464` — «tile required» |
| `propose_trade` | **отказ всегда** | `engine.gd:557–559` — «invalid recipient» |
| `respond_trade` | **молчаливый отказ** от любой сделки (`accept=false` по умолчанию, `engine.gd:585`) — акцепта нет нигде | — |
| `bid` | шлёт **$0**: первая ставка принимается при `high=-1`, после чего «0 ≤ 0» → перебить нельзя (`engine.gd:176–188`); против ИИ-ставок человек бессилен | — |
| `end_turn` | не появляется никогда (нет в `legal_actions`) | бейдж «N» — наклейка |
| хоткеи «B/N» | обработчиков клавиш в панели нет | наклейка (F-29) |

Инспектор (`tile_inspector.gd`) — **единственный** рабочий путь стройки/залога: он
шлёт `{"tile": …}` при выбранной клетке.

### 3.3 Модалок решений нет
`modal_host.gd` умеет только `show_message(title,text)` («richer modals can land in it
later»). Отсутствуют: F-40 стройка/залог, F-41 составление торга, F-42 входящий торг,
F-43 аукцион. Следствие: человек **не может** ни предложить сделку, ни принять её, ни
ввести ставку.

### 3.4 Компакт-профиль: доки исчезают без замены
`game_view.gd:138–142`: при ширине `<1280` или высоте `≤700` `seats` и `rightcol`
(тосты+журнал+инспектор) скрываются, и **ничего не открывается взамен** — рейлы 48px и
ящики `drawer_panel` остались в архиве. Инспектор — единственный путь стройки — пропадает
вместе с доком. Спека I-10/P-16 требует рабочий режим 880×600. Проверено пробой: на
1000×650 `visible=false` у обоих доков (§8.4).

### 3.5 Идентичность места: UI не знает, «за кого» он играет
- `game_view.gd:37,168` — `_human_pid := 0` захардкожено (в старом UI вычислялось из
  LOCAL-места). На хосте «работает» случайно; у удалённого клиента (место 1+) кнопки не
  покажутся никогда, а интенты ушли бы «за место 0».
- `main.gd:215–237` — `_on_remote_state` **безусловно** авто-отвечает `legal[0]`
  (авто-ролл/авто-пас): смоук-механика осталась в продакшене. Даже после возврата джойна
  живой игрок в браузере получил бы автоигру без возможности выбора.
- `_observer` (`game_view.gd:36`) не выставляется никогда; поля `UiProfile`
  (`shows_actions`, `input_enabled`, `header_full`, `text_scale`, `data_source`) не читает
  никто в новом UI → `--stream` — тот же интерактивный экран, что у хоста (ввод не запрещён).

### 3.6 Тексты: ключи вместо строк

## 4. SDK (Neuro) — три независимых разрыва

1. **UI не может создать SDK-место** (§3.10): водители хардкодятся, других писателей
   `seat_assignments` в продукте нет (только `main._autostart` по CLI и оверлей).
2. **Рантайм не спавнит адаптер**: `resolve_driver("sdk:neuro") → "SDK"`, но `seat_manager`
   для «SDK» не создаёт никого (`seat_manager.gd:~40–55`, `153–157` — «SDK seats are NOT
   auto-passed»); единственный код, создававший `SdkAdapter`, — архивный
   `seats_soak.gd:16,63–64`. SDK-место в живом матче = вечное ожидание.
3. **Соединение не настраивается**: аддон читает `NEURO_SDK_WS_URL` из окружения и печатает
   `ERROR: NEURO_SDK_WS_URL environment variable is not set` при **каждом** запуске, включая
   headless-тесты и браузерную сборку у зрителя. Ограничение «один SDK на процесс»
   задокументировано (`seat_config.gd:82–86`: второй SDK-слот падает в AI).

Тесты `sdk_test` (19) проверяют чистую логику (projection/renderer/decision) — и зелёные.
Рантайм-склейки нет.

## 6. Процессные уроки (почему это стало возможным и что обязан сделать новый сеанс)

1. **Не было ни одного сквозного гейта на интерфейс.** Тесты проверяли ядро; UI жил на
   «SMOKE PASSED» по стейл-сборкам и на самореферентных дизайн-гейтах (макет генерируется
   из игры — «палитра сошлась» ничего не доказывает).
2. **Порог понизили вместо сигнализации** (`MIN_TESTS 400→270` в том же коммите, что выбросил
   127 тестов); обещанные замены-пробы (`coverage.md` §6) не появились.
3. **Документы опередили реальность** (`ui-integration-status.md` описывает уже снесённое
   дерево; `plan.md` объявляет DONE красный инструмент). Док обязан рождаться из свежего
   прогона; сгнил — правится тем же коммитом, что и код.
4. **Стейл-артефакты считались доказательством.** Правило №5 из `ui-fix-plan.md` («артефакт
   пересобирается, иначе правки не существует») нарушил сам своп.
5. **FPS-бюджет I-7 (≥40 в браузере) не проверяется** — в CI его нет; статус честно признаёт,
   что порог красный у обеих сборок на загруженной машине.
