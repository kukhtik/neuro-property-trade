# NPT — программа гейтов восстановления (hard + soft)

> Пара к `docs/restoration/plan.md`. Все адреса — на снимке `effb831` (13.10.2026).
> **Жёсткие (HG)** — функциональность: красный гейт = остановка. **Мягкие (SG)** — внешность
> и юзабилити: две ступени внутри (SG-assert — авто-проверка объективных инвариантов, тоже
> красная; SG-report — отчёт/скриншоты для глаз, никогда не блокирует).

---

## 0. Философия «мягких» тестов (почему именно так)

Интерфейс может меняться — дизайн не заморожен. Поэтому мягкие гейты **не фиксируют
внешность** (никаких пиксель-диффов против макета как порога — смоук прямо говорит:
«порога „похоже" не существует»). Мягкие гейты ловят то, что объективно плохо при
**любом** дизайне:

* **структура** — регион исчез, элемент недостижим, ничего не видно в компакте;
* **читаемость** — текст обрезан, вылез за кадр, перекрыт тостом, показан ключом `{x}`;
* **согласованность** — цвет вне палитры скина, роль текста нарушена, язык не переключился;
* **деградация со временем** — «было 0 обрезанных меток, стало 12».

Итог: SG-assert — красный (это инварианты, а не вкус). SG-report — артефакт для ревью
(скриншот-серия, side-by-side, fps). Вкусовое решение всегда за владельцем, но **отчёт
сгенерировать обязан каждый прогон** — «нет отчёта» = красный.

Три правила допусков:
1. **Допуск задан здесь и редактируется только осознанно** (коммит с обоснованием).
2. У каждого авто-гейта есть **allowlist** (арт, антиалиасинг, тени) — расширяется коммитом.
3. Гейт, который нельзя объяснить человеку одной строкой причины — не гейт.

## 1. Инфраструктура (создаётся в фазе 0)

```
game/tools/gates/<id>_gate.gd|.tscn    # по гейту на сцену (образец — v3_probe.gd)
tools/ci/run_gates.sh                  # раннер: --hg | --sg | --all | --report-only
build/gates/report.html                # сводный отчёт (вердикт + причина + ссылки на кадры)
build/gates/<id>.json                  # машиночитаемый результат
build/renders/<state>_<skin>.png       # скриншот-серия (SG-07)
```

* Раннер повторяет дисциплину `run_probes.sh`: вердикт — **по строкам** (`PASSED`/`FAILED`),
  `SCRIPT ERROR` = провал; exit code Godot — вторичен (падает при выходе).
* **Карантин → CI.** Новый гейт регистрируется в раннере статусом `quarantine`
  (гоняется локально/по запросу), после стабильно зелёных прогонов переводится в `required`
  отдельным коммитом и добавляется шагом в `.github/workflows/ci.yml`. Пока P0 не починен,
  все новые гейты — в карантине; сам факт прогона и статусы обязаны быть в отчёте.
* Каждый гейт печатает **человеческую причину**: что, где (`файл:строка` / регион / ключ),
  как воспроизвести.
* Минимальный набор «железа» для гейтов уже есть: `MainScript._autostart` (матчи по CLI),
  `seat_manager.push_intent`, `projection.for_spectator/for_player`, тестовый хук `_force_dice`,
  `--smoke-drive/--proxy-remote`, `seats_soak` в архиве (порт обратно — фаза 3).

## 2. ЖЁСТКИЕ гейты (HG) — функциональность

### HG-01 · Целостность оракула · P0-infra · CI
**Доказывает:** набор тестов не может тихо сжаться; «зелёно» значит «зелёно».
**Как:** (а) `run_tests.sh` как есть; (б) в `game/tests/run.gd` добавить чек «каждый
`game/tests/*_test.gd` присутствует в `modules`» (ловит сироту `theme_test.gd`, 6 тестов);
(в) правило `MIN_TESTS`: только вверх; понижение — лишь с объяснением и планом возврата в том же коммите.
**Критерий:** импорт-проход без `SCRIPT ERROR`, `ran N ≥ MIN_TESTS`, `0 failed`, сирот нет.

### HG-02 · Полный человеческий цикл из UI («robot human») · **P0, главный гейт** · CI
**Доказывает:** каждое легальное действие **выполнимо из интерфейса** и принято движком.
**Как:** сцена (образец — `console_actions_probe.gd`): реальный `MainScript`, матч
1 LOCAL + 3 AI по фиксированному сиду; скрипт ждёт свои ходы и **жмёт настоящие кнопки**
(из `_btn_row` / инспектора / модалок), собирая: `roll`; `buy`/`pass` в PURCHASE_WAIT;
`build_house`/`sell_house`/`mortgage`/`unmortgage` (инспектор: выбрать клетку → кнопка);
`pay`/`use_card` в тюрьме; `propose_trade` (модалка) и `respond_trade` (accept и decline);
`bid` с суммой; подтверждения. Ассерты: каждый intent `ok=true`; фаза/лог двигаются;
матч доходит до `END_GAME` или `round_limit`. Все действия из спек-инвентаря F-26,
F-37–F-45, F-39 должны быть покрыты хотя бы раз. Отчёт: таблица «действие → чем нажато → результат».
**Критерий:** ни одного отказа по вине UI (отказы движка по правилам допустимы и логируются);
хотя бы один матч до конца; `SCRIPT ERROR` = 0.

### HG-03 · Аукцион из UI · P0 · CI
**Доказывает:** человек участвует в аукционе на равных с ИИ.
**Как:** форсировать аукцион (`_force_dice` на чужую клетку / пас владельца при
`auctions_on_refusal`); кнопка СТАВКА открывает ввод суммы → ставка > текущей (в т.ч.
перебивание ИИ-ставки; отказ движка «bid must exceed» без UI-пути = провал гейта);
пас; наблюдатель (не текущий биддер) **не имеет** кнопок ставки; счётчик ставок виден.
**Критерий:** ≥2 круга перебивания человек↔ИИ; победа и проигрыш аукциона воспроизведены.

### HG-04 · Торговля из UI · P0 · CI
**Доказывает:** человек торгует в обе стороны.
**Как:** модалка состава (give/want: tiles+cash, валидация владения/денег) → отправка →
вторая сторона: принять (кнопка, `accept=true`) и отклонить; AI→человек оффер (negotiator
шлёт только «проходимые» офферы) → человек **принимает** из UI; отказ с причиной движка
человеческим языком («Причина: …»).
**Критерий:** 4 сценария (человек→AI принять/отклонить ИИ, AI→человек принять, невалидный состав отклонён движком с человеческой причиной).

### HG-05 · Идентичность места и адресация интентов · P0 · CI
**Доказывает:** UI действует только «за себя»; никто не играет за человека.
**Как:** (а) матч 1 LOCAL + 3 AI: интенты уходят только при `holder == local`; нажатия в
чужой ход невозможны (кнопок нет); (б) remote-клиент (второй процесс, `--smoke-seats=2`):
кнопки появляются **на своём** ходу (после ремонта `_human_pid` — фаза 1), интент уходит
с правильным pid; (в) прогон **без** `--smoke-drive`: `_on_remote_state` не смеет
отправлять ни одного intent (авто-ответ запрещён), с флагом — отправляет.
**Критерий:** ноль «чужих» интентов во всех трёх сценариях.

### HG-06 · Джойн/инвайт сквозной на свежей сборке · P0 · CI (после Phase 1)
**Доказывает:** друг открывает ссылку и играет; хост видит честную ссылку.
**Как:** одиночный прогон: экспорт web **в этом же прогоне** (абсолютный путь!) → хост
(`--admin --server-port … --autostart --smoke-seats=…`) → настоящий браузер по ссылке с
токеном → `JOINED`, ≥1 `VERDICT ok=true`, ход виден в хосте. Инвайт-экран показывает
**реальный** `ws://` адрес и токен (не заглушку). Основа — существующий
`tools/ci/browser_seat_e2e.py` (сейчас красный: `joined=False`) + `smoke_all_roles.py`.
**Критерий:** `joined=True`, accepted ≥ 1, матч прогрессирует; экспорт/кадр не старше начала прогона.

### HG-07 · Настройки матча · P0/P1 · CI
**Доказывает:** заявленный состав партии конфигурируем и применяется.
**Как:** через UI (или напрямую через оверлей в пробе): собрать матч с местами
LOCAL/AI/REMOTE/CHAT/`sdk:neuro` — состав `seats` совпадает (водители, имена, цвета,
персоны); `START` создаёт ровно это; `APPLY` в игре **не сбрасывает** поля (оверлей
отражает текущие настройки, а не дефолты); числовые поля валидируются (сид/кэш/раунды/таймер).
**Критерий:** 2 конфигурации (соло 1+3AI; сетевая 1+REMOTE+AI) собираются и стартуют;
повторный APPLY сохраняет пользовательские значения.

### HG-08 · SDK-место в рантайме · P1 · CI (после Phase 3)
**Доказывает:** Neuro-место играет.
**Как:** матч с seat driver `SDK`; в дереве появляется `SdkAdapter` (сейчас не появляется
никто — спавн добавить в `seat_manager`); мок-WS сервер (локальный, отдаёт startup_ack)
→ место получает force-окно и отвечает; матч не стопорится и завершается.
**Критерий:** адаптер существует, ≥1 ход SDK-места принят, ноль стопов; вернуть из архива
`seats_soak` (SDK+AI+AI+LOCAL) как второй сценарий.

### HG-09 · Контракт i18n · P0 (дешёвый, высокий улов) · CI
**Доказывает:** пользователь никогда не видит `{ключи}`.
**Как:** (а) статический скан `game/ui|visual|main` на `I18n.t("…")`/`has("…")` + динамические
префиксы (`"phase."+ph`, `"event_type."+kind`) — каждый ключ резолвится в ru и en;
(б) поведенческий: обойти живое дерево после сценариев HG-02 — ни одна `Label/Button`
не содержит текста вида `{x.y}` (сейчас: 5 живых мест — `over.title/over.winner/plr.jail/
stat.round/top.decision`).
**Критерий:** 0 нерезолвленных ключей, 0 `{…}` в видимом тексте. (Фикс 5 ключей входит в фазу 0.)

### HG-10 · Контракт проекции · P1 · CI
**Доказывает:** UI не читает несуществующие поля.
**Как:** тест пинит ключи, которые UI читает (`round`, `turn_player`, `phase`, `players[].*`,
`board[].*`, `pending.*`, `parking_pot`, `timer_window/elapsed/active`, `legal`) против
фактических выходов `projection.for_spectator()` и `for_player()`; отдельный скан кода
на `proj.get("…")`/`spec.get("…")` с проверкой по списку. Регрессия `pot vs parking_pot` —
прямой тест-кейс.
**Критерий:** ни одного чтения ключа вне контракта; при добавлении ключа — правка контракта тем же коммитом.

### HG-11 · Свежесть артефактов и кадров · P0-infra · CI
**Доказывает:** «зелёно» относится к текущему коду, а не к прошлонедельному файлу.
**Как:** (а) смоук/браузерные гейты **сами** экспортируют сборку в свой `build/…` каталог;
(б) `compare_mockup.py` читает кадр **своего** прогона (параметр `NPT_FRAME`, не
хардкод `build/smoke/admin.png`), при отсутствии — честный SKIP с причиной;
(в) скрипт `tools/ci/check_freshness.sh`: для каждого артефакта в `build/` время ≥ времени
последнего коммита, трогающего `game/` (иначе — красный или явное «артефакт намеренно архивный»).
**Критерий:** ни один отчёт не может опираться на файл старше кода, который он якобы проверяет.

### HG-12 · Роли-исполнения · P1 · CI
**Доказывает:** эфир/админ/веб ведут себя как заявлено (I-3).
**Как:** запуск `--stream`: профиль `observer` — ввод не проходит (симулированный клик/
интент отбрасывается, `input_enabled=false` уважается), расклад наблюдателя активна
(журнал шире, места свёрнуты, «паузы нет»), автодетект «нет LOCAL → observer»;
`--admin`: F12 открывает панель (сборка админ-панели уже проверена пробой — 36 лейблов/31
кнопка); web: админ-элементов нет вовсе.
**Критерий:** три роли изолированы; ни один интерактивный элемент эфира не мутирует партию.

### HG-13 · Хоткеи и таймер · P1/P2 · CI
**Доказывает:** обещанное управление и обратная связь о времени работают.
**Как:** B/N — реальные `InputEventKey` → действие летит в движок (иначе бейджи убрать из
кнопок и из спеки-факта); таймер: `turn_timer>0` → в UI видно кольцо/остаток (данные уже
приходят: `timer_window/elapsed/active` в `state_changed`), `0` → виджета нет; по истечении
— `away`/auto-pass по настройке.
**Критерий:** клавиши работают, таймер отображается и срабатывает; при выключенном лимите — ничего.

## 3. МЯГКИЕ гейты (SG) — внешность и юзабилити

### SG-01 · Регионы и достижимость на всех профилях · assert · CI
**Проверяет:** ни одна зона не «исчезает». Профили: 1440×900, 1280×720, 1000×650, 880×600
(и компакт-высота). Для каждого региона `design/regions.json`: либо видим, либо **заменён**
(рейл/ящик/тикер консоли); недостижимых нет. Текущий провал: 1000×650 — `seats`/`rightcol`
`visible=false` без замены (сид — `compact_probe.gd`).
**Критерий:** 0 недостижимых регионов на 4 профилях; допуск позиций ±2px от макетных метрик (56/268/344/96).

### SG-02 · Влезание и клиппинг (RU+EN) · assert · CI
**Проверяет:** ничего не вылезает за вьюпорт и текст не обрезан. Скан всех видимых
Control: `global_rect` внутри окна (±2px); для Label/Button — минимальный размер ≥
содержимого (+4px) при `AUTOWRAP_OFF`; ellipsis — только по allowlist (компакт-имена,
рейлы). Гонять в RU и EN (RU длиннее).
**Критерий:** 0 нарушений среди видимых вне allowlist на 4 профилях × 2 языках.

### SG-03 · Палитра кадра ⊆ токены скина · report (fail после калибровки)
**Проверяет:** интерфейс не «переоделся» мимо токенов. Кластеризация пикселей кадра;
каждый кластер ≥N px должен быть в Δ≤8 от палитры скина или в allowlist (арт, антиалиасинг,
тени). На старте — только отчёт; после калибровки allowlist — красный на новые
необъяснённые цвета.

### SG-04 · Роли текста и grow-аудит (P-3/P-4) · assert · CI
**Проверяет:** две роли и только две. Каждая метка: либо значение (`AUTOWRAP_OFF`,
`SHRINK_BEGIN`), либо абзац (`WORD_SMART`, `EXPAND_FILL`); третьей комбинации нет; в
каждой горизонтальной строке ≤1 растягивающийся элемент. Аудит по живому дереву.
**Критерий:** 0 нарушений; это прямой сторож регрессии `3d6928c`.

### SG-05 · Тост-гвард · assert · CI
**Проверяет:** уведомления не перекрывают игру. Прямоугольники тостов не пересекаются с
`stage`/`act`/`modal` на wide/desktop/compact (в компакте тост — строка в консоли, не поверх).
**Критерий:** 0 пересечений на 4 профилях.

### SG-06 · Журнал и читаемость · assert-скан · CI
**Проверяет:** лента объясняет партию. В строках: имя места цветом, текст с **названиями
клеток словами** (никаких «клетка N»/«tile N»), переведённый тег категории; счётчик
«показано/всего»; дружелюбное пустое состояние; фильтры и экспорт существуют.
Реализация — расширение `EventAdapter` (лежит без дела), скан строк живого дерева.
**Критерий:** 0 строк с номерами клеток/ключами; наличие счётчика/фильтров/экспорта.

### SG-07 · Скриншот-серия состояний + side-by-side · report · локально/CI-артефакт
**Проверяет:** «глазами» — каждое состояние против эталонов `design/renders/`. ~12 сцен
(cold, ход человека, ход ИИ, покупка, аукцион, торг, тюрьма, стройка, наблюдатель, компакт,
победа, админ) × стили neuro/evil; обязателен `side_by_side.png` (макет ↔ приложение).
**Красный только за:** пустой/однотонный кадр, исчезнувший регион, `side-by-side failed`.
Остальное — материал для ревью (владелец/vision), порога «похожести» нет.

### SG-08 · Живая локализация · assert · CI
**Проверяет:** RU↔EN переводит всё **без ребилда**. После переключения: ни одной строки
старого языка в дереве, ни одного `{ключа}`; композитные строки пере-выводятся из состояния
(подключить `locale_changed` во все панели — сигнал уже существует).
**Критерий:** 0 остатков после 2 переключений на матче в разгаре.

### SG-09 · Скины · assert · CI
**Проверяет:** скин — один источник цвета. Полнота набора (существующий `skin_probe`);
переключение в **живом матче** без остатка старых цветов; клетка=фишка=строка=журнал —
один цвет места; палитра после переключения ⊆ токенов нового скина.
**Критерий:** 4 скина (neuro/evil/default/classic) переключаются на живом матче чисто.

### SG-10 · Перф-отчёт · report · локально (обязателен) + CI (запись)
**Проверяет:** бюджет I-7 (веб ≥40 FPS). Только `tools/fps_clean.py`, только на чистой
машине; в CI — запись числа в отчёт без порога (окружение шумное), локально у владельца —
порог ≥40 median.
**Критерий:** число опубликовано с обстановкой; локальный порог зелёный у обеих ролевых сборок.

### SG-11 · Юзабилити-чеклист · assert + report · CI
**Проверяет:** интерфейс объясняется сам. Авто: тултип у каждого интерактивного элемента,
сообщения об отказе начинаются с «Причина:» (человеческий язык из ответа движка), RU-запас
в кнопках (ширина ≥ текста + padding). Ручной чек-лист в отчёте: фокус-порядок, отсутствие
тупиков, «одно герой-действие на ход» (P-7).
**Критерий:** авто-часть — 0 нарушений; ручная — заполнена в отчёте.
